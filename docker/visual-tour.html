First, keep this picture in your head

Docker is a short pipeline. You write the first two things; Docker creates the last two.

{ } App files Your code and dependencies
+
▤ Dockerfile The build instructions
→
▱ Image A saved, read-only package
→
▶ Container A running copy of the image
The two verbs

docker build turns files into an image. docker run turns that image into a container. If these two arrows make sense, the rest of Docker has somewhere to fit.

What survives each action?

Most beginner confusion comes from treating an image and a container as the same thing. Compare the result of each command.

Stop

docker stop web

ImageStill there
ContainerStill there, stopped

You can start the same container again with docker start web.

Remove container

docker rm web

ImageStill there
ContainerGone

You can create a fresh container from the same image.

Remove image

docker rmi nginx:alpine

ImageGone
ContainerMust be removed first

Docker can pull or build the image again when you need it.

Remember

  • Build: app files + Dockerfile → image.
  • Run: image → container.
  • A port mapping sends traffic from a host port to the port where the app listens inside the container.
  • Stopping or removing a container does not remove its image.
  • A container is disposable. Important data belongs in a volume, which you will learn later.
