Everyday commands

About twenty commands cover almost all daily work. Each one is explained here with one small example, grouped by what you are trying to do.

How a Docker command is built

Every command has the same shape:

docker  <object>  <action>  [options]  [target]
docker  container  ls       -a
docker  image      pull                nginx:alpine
docker  volume     rm                  notes

The objects are container, image, volume, network and system. The most used commands also have a short form, which is what most people type:

Short formLong form
docker psdocker container ls
docker rundocker container run
docker imagesdocker image ls
docker rmidocker image rm
docker pulldocker image pull
Stuck?

Add --help to any command: docker run --help, docker volume --help. The help text lists every option.

Work with images

Reading an image name

docker.io / library / postgres : 17-alpine
 registry   namespace  repository   tag
  • You normally write only postgres:17-alpine. Docker fills in the registry (docker.io, which is Docker Hub) and the namespace library (official images).
  • No tag means latest. latest is only a default label. It does not promise the newest version, and it points to a different image over time. For real projects, always write a version.
  • -alpine = built on Alpine Linux, very small. -slim = a reduced Debian. No suffix = the full variant.
CommandWhat it doesExample
docker pullDownload an image without running itdocker pull postgres:17-alpine
docker imagesList the images on your machine with their sizedocker images
docker image inspectShow every detail of an image as JSONdocker image inspect nginx:alpine
docker historyShow the layers of an image and their sizedocker history nginx:alpine
docker rmiDelete an image (fails while a container uses it)docker rmi nginx:alpine

Run a container

docker run is the command you will type most. It creates a new container from an image and starts it.

docker run [options] IMAGE [command to run inside]
The order matters

Options go before the image name. Everything after the image name is handed to the container as its command. docker run nginx:alpine -d does not run in the background: it tries to run a program called -d inside the container.

OptionWhat it doesExample
-dRun in the background (detached)docker run -d nginx:alpine
-p HOST:CONTPublish a container port on your machine-p 8080:80
--nameGive the container a name--name web
-e KEY=valueSet an environment variable (configuration)-e POSTGRES_PASSWORD=secret
--env-fileRead many variables from a file--env-file .env
-itInteractive terminal, for a shelldocker run -it alpine sh
--rmDelete the container when it exitsdocker run --rm alpine date
-vAttach storage (see Data & networking)-v db_data:/var/lib/postgresql/data
--networkJoin a network (see Data & networking)--network labnet
--restartRestart automatically after a crash or reboot--restart unless-stopped

Three examples you can run now:

# A web server in the background, reachable at http://localhost:8080
docker run -d -p 8080:80 --name web nginx:alpine

# A throw-away Linux shell to look around. Type "exit" and it is deleted.
docker run --rm -it alpine sh

# One command, then the container is gone. Prints the date inside the container.
docker run --rm alpine date
Every run is a new container

Run the same command three times and you have three containers. docker run never reuses an old container, and docker build never creates one. What happens when you change your code and build again is the subject of Change, build, run.

The life of a container

A container is always in one of a few states. The most important thing to remember: stopping is not deleting.

CommandWhat it doesExample
docker psList running containersdocker ps
docker ps -aList all containers, also stopped onesdocker ps -a
docker stopAsk the app to shut down (about 10 seconds grace, then it is killed)docker stop web
docker startStart a stopped container again, with the same filesdocker start web
docker restartStop, then startdocker restart web
docker rmDelete a stopped container and its filesdocker rm web
docker rm -fKill and delete a running container in one stepdocker rm -f web

Look inside a container

When something does not work, these are the commands that tell you why. Always start with the logs.

CommandWhat it doesExample
docker logsPrint what the app wrote to its outputdocker logs web
docker logs -fKeep following new lines (Ctrl+C to stop watching)docker logs -f --tail 50 web
docker exec -itOpen a shell in a running containerdocker exec -it web sh
docker execRun one command in a running containerdocker exec web ls /etc/nginx
docker inspectShow all settings as JSON: ports, mounts, environment, statedocker inspect web
docker statsLive CPU and memory use per containerdocker stats
docker topProcesses running in a containerdocker top web
docker cpCopy a file out of (or into) a containerdocker cp web:/etc/nginx/nginx.conf .
run or exec?

docker run creates a new container. docker exec runs a command inside a container that already exists and is running. To look inside your app, you want exec.

sh or bash?

Small images such as Alpine do not include bash. If you see exec: "bash": executable file not found in $PATH, use sh instead.

Clean up safely

Docker never deletes anything by itself. Old images, stopped containers and build cache pile up until the disk is full. First look, then delete.

$ docker system df
TYPE            TOTAL     ACTIVE    SIZE      RECLAIMABLE
Images          12        10        6.1GB     1.2GB (19%)
Containers      14        12        310MB     40MB (12%)
Local Volumes   9         8         2.4GB     120MB (5%)
Build Cache     45        0         1.8GB     1.8GB

The numbers above are only an example. Reclaimable is what you could get back.

CommandWhat it removesRisk
docker system dfNothing. It only shows disk usage.Safe
docker container pruneAll stopped containersLow
docker image pruneDangling images: old, nameless leftovers from rebuildsLow
docker builder pruneUnused build cache. The next build is slower.Low
docker system pruneStopped containers, unused networks, dangling images, unused build cacheMedium
docker image prune -aEvery image that no container uses. They must be downloaded again later.Medium
docker system prune -a --volumesAll of the above, plus all unused images and unused anonymous volumesHigh
docker volume prune -aEvery volume no container uses, including named ones. This is where databases are lost.High
Prune works on the whole machine

A prune command does not know about "your project". It removes unused things from every project on that machine. A database that happens to be stopped counts as unused. Read the list Docker shows before you answer y, and on a shared server, ask first.

Hands-on lab

Do these in your terminal. Each step has the answer hidden below it. The last two steps show the most important behaviour in this module.

  1. Start nginx:alpine in the background, named lab, on host port 8081, and open it in the browser.
    Answer
    docker run -d -p 8081:80 --name lab nginx:alpine

    Then open http://localhost:8081.

  2. Change the home page from inside the container, then refresh the browser.
    Answer
    docker exec lab sh -c 'echo "Hello from inside" > /usr/share/nginx/html/index.html'

    The page now says Hello from inside.

  3. Stop the container. Is it listed by docker ps? By docker ps -a?
    Answer
    docker stop lab
docker ps
docker ps -a

    docker ps does not show it. docker ps -a shows it with the status Exited (0). It still exists.

  4. Start it again and refresh. Is your change still there?
    Answer
    docker start lab

    Yes. Stopping keeps the files of the container.

  5. Remove it and run a new container with the same command as in step 1. Is your change still there?
    Answer
    docker rm -f lab
docker run -d -p 8081:80 --name lab nginx:alpine

    No. You see "Welcome to nginx!" again. A new container starts fresh from the image. Keeping data across containers is the job of volumes, in Data & networking. Clean up with docker rm -f lab.

Practice

Type each command from memory. If you are wrong, the checker tells you which piece is missing.

Remember

  • The pattern is docker <object> <action>. Options go before the image name.
  • run creates a new container. start restarts an old one. exec works inside a running one.
  • stop keeps the container and its files. Only rm deletes them.
  • When something is wrong: docker ps -a, then docker logs NAME.
  • Run docker system df before any prune, and never prune volumes without thinking.
