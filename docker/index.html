What is Docker?

Docker packs an application together with everything it needs, so it runs the same way on every machine. This page explains the idea in plain language, then you start your first container.

How this learning path works

Go through the modules in order. Every lesson follows the same rhythm: a short explanation, a picture, a command you run yourself, then exercises that check your answer. You need a terminal and about four to five hours in total.

The problem Docker solves

You have probably heard this sentence: "But it works on my machine."

An application needs more than its own code. It needs a language runtime (Python 3.13, Node 24), libraries, system packages and settings. Your laptop has one combination. Your teammate's laptop has another. The server has a third. The same code behaves differently in each place.

Without Docker

  • You: Python 3.13, Ubuntu, library v2
  • Teammate: Python 3.10, macOS, library v1
  • Server: Python 3.11, another Linux
  • Result: three different behaviours, long setup documents, bugs that only appear in production

With Docker

  • You build one package: code + Python + libraries + settings
  • Your teammate runs that same package
  • The server runs that same package
  • Result: the same behaviour everywhere, setup is one command
Think of it like this

Before shipping containers, goods were loaded onto ships piece by piece, and every port handled them differently. Then the world agreed on one standard steel box. Any crane, ship or truck can move it without caring what is inside. Docker is that standard box for software.

Four words you need

Almost everything in Docker is built from these four ideas.

WordWhat it isKitchen comparisonProgramming comparison
DockerfileA text file with the steps to build an imageThe recipeSource code
ImageA read-only package: your app plus everything it needsA frozen ready meal made from the recipeA class
ContainerA running instance of an imageThe meal, heated and on the tableAn object created from the class
RegistryA server that stores and shares images (Docker Hub is the default)The supermarket freezerGitHub, but for images
  • An image never changes. To change it, you build a new one.
  • One image can start many containers. Each gets its own private, writable copy of the files.
  • A container is just a process with its own isolated files, network and process list.
  • Deleting a container does not delete the image. You can start a fresh one at any time.
Check yourself: you start three containers from one image and delete a file in the first. What happens in the other two?

Nothing. Each container has its own writable layer on top of the shared read-only image. Changes in one are invisible to the others, and the image itself stays untouched.

Containers and virtual machines

Both let you run isolated software on one computer. The difference is what each one carries with it.

Virtual machineContainer
ContainsA full guest operating system plus the appThe app and its libraries only
KernelIts ownShared with the host
Typical sizeGigabytesTens to hundreds of megabytes
Start timeTens of seconds to minutesAbout a second
IsolationStronger (separate kernel)Good, but the kernel is shared
Use it whenYou need a different operating system or very strong isolationYou want to package and run applications
Good to know

They are not rivals. In the cloud, containers usually run inside virtual machines. And because containers need a Linux kernel, Docker Desktop on macOS and Windows quietly runs a small Linux virtual machine for you.

How Docker works behind the scenes

Docker has three parts. The docker command you type is only a remote control. The real work is done by a background program called the Docker daemon (also called the Docker Engine). The daemon talks to a registry when it needs an image.

Click through: what happens when you run a container

The command is docker run -d -p 8080:80 nginx:alpine. Press Next step to follow it.

1. You type the command

The docker program reads your command and sends a request to the Docker daemon. The CLI itself does not run anything.

2. The daemon looks for the image locally

"Do I already have nginx:alpine on this machine?" If yes, it skips the next step. That is why the second run is much faster than the first.

3. Not found, so it pulls from the registry

The daemon downloads the image from Docker Hub, layer by layer. You see lines such as Pulling fs layer and Pull complete. This happens only the first time.

4. It creates a container

The daemon adds a thin writable layer on top of the read-only image and gives the container its own network address and its own view of the files.

5. It connects the port

Because of -p 8080:80, traffic that arrives at port 8080 on your machine is forwarded to port 80 inside the container.

6. It starts the main process

The image says which program to start, here the nginx web server. The container lives exactly as long as this process runs. When it ends, the container stops.

7. You open the browser

Go to http://localhost:8080 and nginx answers. Because of -d, your terminal is free again while the container runs in the background.

Install and check

Install Docker Desktop on macOS or Windows, or Docker Engine on Linux, from the official guide: docs.docker.com/get-started/get-docker. Then check that it works:

$ docker --version
Docker version 29.8.0, build 88096ef
$ docker compose version
Docker Compose version v5.5.1
$ docker run hello-world
Hello from Docker!
This message shows that your installation appears to be working correctly.

Your version numbers will be different. What matters is that all three commands answer without an error.

Linux: "permission denied"

If you see permission denied while trying to connect to the Docker daemon socket, your user is not allowed to talk to the daemon yet. Run sudo usermod -aG docker $USER, then log out and log in again. Be aware that members of the docker group effectively have root access to the machine.

Your first real container

Start a web server, look at it, and clean up. Run the lines one at a time.

$ docker run -d -p 8080:80 --name web nginx:alpine
$ docker ps
CONTAINER ID   IMAGE          COMMAND                  CREATED         STATUS         PORTS                  NAMES
867f4dfa1a47   nginx:alpine   "/docker-entrypoint.…"   5 seconds ago   Up 5 seconds   0.0.0.0:8080->80/tcp   web

Now open http://localhost:8080. You should see "Welcome to nginx!". You are running a web server without installing one.

PartMeaning
docker runCreate a new container and start it
-dDetached: run in the background and give the terminal back
-p 8080:80Publish a port. Left is your machine, right is the container: HOST:CONTAINER
--name webA name you choose, so you do not need the random container ID
nginx:alpineThe image: repository nginx, tag alpine (a very small variant)

Look at what the server logged, then stop and remove it:

$ docker logs web
$ docker stop web
$ docker rm web
If port 8080 is busy

The error Bind for 0.0.0.0:8080 failed: port is already allocated means something else on your machine uses that port. Change only the left number, for example -p 8081:80, and open localhost:8081.

Practice

Type the answer and press Enter. Options may be in any order. Nothing is sent anywhere: the check runs in your browser.

Remember

  • Docker packs an app with everything it needs, so it runs the same everywhere.
  • Dockerfile (recipe) → image (package) → container (running instance). Images are shared through a registry.
  • Containers share the kernel of the host. That is why they are small and start in about a second.
  • The docker command is a remote control for the Docker daemon.
  • A container lives as long as its main process runs.
