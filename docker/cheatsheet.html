Dockerfile

FROM python:3.13-slim
WORKDIR /app
RUN useradd --create-home appuser
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY --chown=appuser:appuser . .
USER appuser
EXPOSE 8000
CMD ["gunicorn", "--bind", "0.0.0.0:8000", "app:app"]
InstructionOne-line meaning
FROMBase image. Pin the version.
WORKDIRFolder for the next steps
COPYBring files into the image
RUNExecute at build time
ENVEnvironment variable. Never a secret.
EXPOSEDocument a port. Does not publish it.
USERDo not run as root
CMDExecute when the container starts. Use square brackets.

What picks up my change?

I changedDo this
Code, plain Dockerdocker build -t app:1.1 . → docker rm -f app → docker run ... app:1.1
Code, with Composedocker compose up -d --build
compose.yaml or .envdocker compose up -d
Nothing; the app is just stuckdocker compose restart web

build makes images and never a container. restart applies no change at all. A container keeps the image it was created from.

Glossary

WordMeaning
ImageA read-only package of an app and everything it needs
ContainerA running instance of an image
DockerfileThe recipe for building an image
RegistryA server that stores images, such as Docker Hub
TagThe label after the colon in an image name; usually a version
LayerThe result of one Dockerfile instruction; layers are cached and shared
Build contextThe folder sent to the build; the dot in docker build .
Daemon / EngineThe background program that builds images and runs containers
VolumeStorage managed by Docker that survives containers
Bind mountA folder of your machine made visible inside a container
Publish a portForward a port of your machine to a port of a container
ServiceOne entry under services: in a Compose file
Health checkA command that tells Docker whether an app is really ready
Dangling imageAn old image with no name, left over after a rebuild
Multi-stage buildA Dockerfile with several FROM lines, to keep build tools out of the final image
