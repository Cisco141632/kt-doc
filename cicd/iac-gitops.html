Infrastructure as Code, Kubernetes and GitOps

Application delivery is repeatable only when its runtime environment is also declared, reviewed and recoverable.

Infrastructure as Code (IaC)

IaC stores the desired infrastructure in version-controlled files. A plan shows the proposed difference; review checks the risk; apply changes the provider; state tracks resource identity.

resource "aws_ecr_repository" "api" {
  name                 = "payments-api"
  image_tag_mutability = "IMMUTABLE"

  image_scanning_configuration {
    scan_on_push = true
  }
}
$ terraform fmt -check
$ terraform validate
$ terraform plan -out=plan.tfplan
$ terraform apply plan.tfplan
Treat plans as sensitive

Plans and state may contain infrastructure details or secret values. Store remote state securely, lock concurrent changes, limit access and never publish plan files as public artifacts.

Helm packages parameterized Kubernetes resources. Kustomize overlays a base without a template language. Both should render inspectable YAML that policy and server-side validation can check before reconciliation.

Push deployment and GitOps

Pipeline pushes

  • CI receives cluster credentials
  • CI runs the deployment command
  • Result depends on pipeline connectivity
  • Direct and familiar

GitOps controller pulls

  • CI updates desired state in Git
  • In-cluster controller detects the change
  • Controller reconciles continuously
  • Credentials stay in the runtime boundary

Reconciliation changes the operating model

If someone manually edits the cluster, a GitOps controller detects drift and can restore the declared state. Emergency changes must therefore be followed by a Git change, or the controller may reverse them.

Learn in this order

  1. Docker images, processes, networking and volumes
  2. A simple pipeline and registry
  3. One-server or managed-platform deployment
  4. Kubernetes workloads, networking, health and resources
  5. Helm/Kustomize packaging
  6. Terraform and remote state
  7. GitOps reconciliation and progressive delivery

Kubernetes is not a prerequisite for CI/CD. Adding it before understanding artifacts, health and configuration usually multiplies unknowns.

Remember

  • IaC makes infrastructure changes reviewable, repeatable and recoverable.
  • Kubernetes runs the same OCI artifacts; it adds scheduling, rollout and reconciliation behavior.
  • GitOps moves cluster credentials out of CI and makes Git the desired-state record.
