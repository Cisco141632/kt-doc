Module 02 / 18 · about 20 minutes

Install, verify & take the first step

Get a working tmux installation, learn the prefix sequence, and practise leaving and returning without losing your shell.

By the end, you can…

  • Install on Linux, macOS or WSL.
  • Tell shell commands, prefix keys and tmux commands apart.
  • Create and reattach to a disposable session.

Install on the machine that will run your work

For remote work, tmux must be installed on the remote host. Installing it only on your laptop does not protect a shell running outside tmux on the server. On Windows, use a Linux environment such as WSL; run the Linux installation commands inside that distribution.

EnvironmentInstallation command
Ubuntu / Debian / Ubuntu in WSLsudo apt update && sudo apt install tmux
Fedorasudo dnf install tmux
Arch Linuxsudo pacman -S tmux
macOS with Homebrew already installedbrew install tmux
openSUSEsudo zypper install tmux
Run in your shell
command -v tmux
tmux -V
man tmux

command -v should print an executable path. tmux -V prints the version, for example tmux 3.4. Press q to leave the manual. Distribution packages can be older than upstream. Read the installed manual before adopting examples from newer releases.

If installation fails

“Command not found” means tmux is missing or absent from PATH. Repository or permission errors belong to the package manager: confirm the OS, repository configuration and administrator access. On a managed host, ask the administrator for the supported package rather than compiling over system files.

Your first five minutes

Run in your shell
tmux new-session -s learn

A shell opens with a status line showing [learn] and its first window. You are now inside tmux. Create a visible marker:

Run in your shell
printf 'This shell belongs to my learn session.\n'
printf 'Pane: %s\n' "$TMUX_PANE"
Ctrl + b → release both → d

You should return to the outside shell with a detached message. Now list the sessions and return:

Run in your shell
tmux list-sessions
tmux attach-session -t learn

The marker and the same shell should still be there. -s names a new session; -t selects an existing target. If “duplicate session: learn” appears, attach to the existing session or choose another name.

The prefix is a sequence, not one chord

Hold Control and press b, release both keys, then press the action key. C-b means Control+b; M usually means Alt/Meta. The default prefix is C-b, but someone’s config may change it. Press Ctrl+b then ? for current bindings; press q to leave that list.

Try a clean configuration

A separate server keeps experiments away from existing work: tmux -L kt-tmux -f /dev/null new-session -s learn. Use tmux -L kt-tmux … for every outside-shell command to that server. The config selection only applies when that server starts.

Leave safely and finish deliberately

Detach when you want to return later. Run exit in a shell when you intend to close that shell. When the last pane closes, its window disappears; when the final window in a session disappears, the session ends. The server normally exits once there are no sessions.

Before practising a close operation, check that you are in the disposable learning session. Avoid kill-server as a troubleshooting reflex: it terminates every session on the targeted server. A stopped program cannot be revived by reattaching.

Pause and test your understanding

Remember in 30 seconds

  • Run tmux where the work runs.
  • Prefix means Ctrl+b, release, then the action key.
  • Detach leaves work running; exit ends the shell.
