Module 12 / 18 · about 35 minutes

Advanced tools & version boundaries

Understand the less common tools, when they help, and which assumptions need checking before use.

By the end, you can…

  • Use isolated servers, grouped sessions and saved layouts.
  • Understand popups, hooks, control mode and recovery limits.
  • Locate version-specific capabilities in the manual.

Isolation is a useful debugging tool

Run in your shell
tmux -L experiment -f /dev/null new-session -s clean
# From an outside shell, inspect only this server:
tmux -L experiment list-sessions

The server is selected by socket. -L is a socket name; -S supplies a complete path. Isolation separates config, sessions and buffers, but it is not a security sandbox: programs still run with your user permissions and can access your files.

The same tmux binary can connect to a server started by an older binary after a package upgrade. Compare tmux -V with tmux display-message -p '#{version}'. Do not kill the old server until its work is finished or deliberately moved to a recoverable state.

Share windows, keep separate current-window choices

Run in your shell
tmux new-session -d -t api -s api-review
tmux attach-session -t api-review

new-session -t api joins a session group based on the existing session. Group members share the window list: creating or removing a linked window is reflected across the group. Their current and previous window choices are independent. Panes and the programs they contain are still shared, including active pane selection within a shared window.

Use this when two trusted viewers want to inspect different windows of one project. Create independent sessions and independent windows if each person needs isolated programs.

Save arrangements; understand what is not saved

Run in your shell
tmux display-message -p '#{window_layout}'
# Later, with a compatible set of panes:
# tmux select-layout -t api:0 'PASTE_THE_SAVED_LAYOUT_STRING'

A layout string describes pane geometry. It does not save files, shell variables, application state or live process memory. Layout restoration works with the panes available at restoration time; it is not a full session backup.

remain-on-exit keeps a pane visible after its main program finishes. Inspect pane_dead and pane_dead_status; use respawn-pane only when you intend to restart its command. respawn-pane -k can replace a still-running program and lose unsaved state.

Tools worth recognizing

ToolWhat it is forImportant boundary
display-popup -EA temporary shell or small tool over the current view (tmux 3.2+).A popup is not another ordinary layout pane; closing it may end its command.
display-menuBuild a menu of tmux actions.Bindings and menu entries execute commands; inspect scripts you import.
command-prompt / confirm-beforeAsk for input or confirm a risky tmux command.Handle shell quoting if that input will reach a shell.
monitor-activity / monitor-silenceNotice output or inactivity in another window.Activity is not equivalent to job success or service health.
lock-client / lock-sessionInvoke the configured lock command.Not a replacement for OS access control; another authorized client can still have access.
tmux -CControl mode for programs integrating with tmux’s protocol.It is a machine interface, not the normal interactive terminal UI.
set-hookRespond to tmux lifecycle events.Inspect hooks when behavior happens unexpectedly.
server-accessPermit or revoke supported multiuser server access.Version-specific; Unix socket permissions also matter. Use least privilege.
Optional tmux 3.2+ popup from an attached session
tmux display-popup -E -w 80% -h 70%

Use exit to close this popup shell. Menus and popups work well for a temporary chooser or help view. Keep long-lived work in an ordinary pane unless you deliberately want the popup lifecycle.

Features evolve; inspect before assuming

Newer tmux documentation may describe floating panes, switch mode, newer client flags and additional format modifiers that an older packaged version does not implement. The upstream getting-started guide labels floating panes and switch mode as 3.8 features. They are optional extensions, not prerequisites for this course’s workflows.

Before adopting a feature, run tmux -V, inspect the server version, use tmux list-commands for syntax and tmux list-keys for actual bindings, then read the matching installed manual. An “unknown command” or “invalid option” can be a version mismatch rather than a typing error.

For complete coverage beyond this curriculum’s examples, read the manual sections on command parsing, key bindings, clients and sessions, windows and panes, buffers, options, formats, hooks, styles, mouse support and control mode. The reference page links those primary sources.

Pause and test your understanding

Remember in 30 seconds

  • A separate server isolates tmux state, not user permissions.
  • Grouped sessions share windows; layout files do not preserve processes.
  • Check both client and server versions before using new features.
