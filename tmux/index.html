Module 01 / 18 · about 10 minutes

Make your terminal a workspace.

Learn tmux from your first session to repeatable development and remote workflows. See what each command changes, try it, diagnose failures, then recall it without looking.

By the end, you can…

  • Understand the problem tmux solves.
  • Choose a learning route and try the browser playground.
  • Know what persistence does—and where it stops.

The problem: one terminal, too much work

You are editing code, watching a server log, and running tests. Another terminal is connected to a remote machine. Which tab belongs to which project? What happens to a long job if the network drops? tmux gives those programs a named workspace that you can leave and return to.

A terminal multiplexer puts multiple terminal programs inside one terminal interface. It runs a server process on the machine where you start it. Your terminal connects as a client. Detaching disconnects the client while programs inside the server’s panes can keep running.

Persistence has a boundary

tmux can outlive a terminal or SSH disconnection. It does not keep processes alive through a host reboot, a stopped container, a killed tmux server, or a policy that terminates your user’s processes on logout.

What you need and how examples work

You need basic shell skills: entering a command, moving between directories with cd, and interrupting a foreground program with Ctrl+c. Installation is covered next. The browser simulator needs no tmux installation; real labs need tmux on Linux, macOS, or Linux inside WSL.

Shell command blocks include the tmux executable. tmux prompt examples are entered after Ctrl+b, release, then :; do not type an extra tmux. Configuration blocks belong in a tmux config file. Expected output blocks are observations, not commands.

The core course targets established tmux 3.2+ behavior. Your installed tmux -V, man tmux, and tmux list-keys are the authority for your version and customization. Optional newer features are labeled. The reference links to the complete manual; this course teaches the full workflow without pretending every version has identical flags.

Everything runs locally in your browser. Progress, lab checklists and quiz results are stored on this browser when storage is available. No account is required. Clearing browser data removes that progress; the recap page lets you export and import a backup.
