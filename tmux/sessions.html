Module 04 / 18 · about 25 minutes

Sessions & the persistence lifecycle

Create named project workspaces, detach, switch and reattach with confidence.

By the end, you can…

  • Create, inspect, rename and switch sessions.
  • Predict which processes survive a disconnection.
  • Distinguish detaching a client from ending a workspace.

Create → work → detach → return

Createtmux new -s api
→
WorkPrograms run in panes
→
DetachCtrl+b then d
→
Returntmux attach -t api
Run in your shell
tmux new-session -s api -n editor
# After detaching:
tmux list-sessions
tmux attach-session -t api

-n editor names the first window. Detaching does not pause or freeze the program: it continues consuming CPU, reading files and writing output. If the program finishes while you are away, you return to its shell or to a closed pane, depending on how you launched it.

A small session toolkit

ActionShell commandAttached shortcut
Create or attachtmux new-session -A -s apiUse an outside shell; inside use session switching.
Create without attachingtmux new-session -d -s workerCommand prompt: new-session -d -s worker
Listtmux list-sessions (alias ls)Ctrl+b then s opens the chooser.
Renametmux rename-session -t api backendCtrl+b then $
Switch attached clienttmux switch-client -t backendChoose a session from the session chooser.
Detach current clienttmux detach-clientCtrl+b then d
Detach other clients when attachingtmux attach-session -d -t backendUse only when you intend to disconnect their views.

Inside tmux, switch-client changes the session displayed by your existing client. Running a new tmux client inside a pane creates nesting, which is usually unnecessary for local session switching. new-session -A is convenient but can silently reuse old project state; inspect the workspace after attaching.

Predict what survives

EventWhat happens
Close the client terminal / SSH dropsThe server and pane programs generally continue on their host; logout policies can change this.
Detach with Ctrl+b dThis client leaves. Other clients may stay attached. Programs keep running.
Ctrl+c in a paneThe terminal sends an interrupt to the foreground process group. Often the job stops and the shell remains.
exit or Ctrl+d at an empty shell promptThe shell may exit. The pane normally closes when its main program ends.
Kill a sessionIts window links disappear; windows with no remaining links close. Programs in closed panes lose their terminals and may terminate.
Server crash / host reboot / container removaltmux does not preserve or resume live processes. Recreate the workspace and restart work from application checkpoints.
A long job needs its own recovery plan

Use application checkpoints and persistent logs. For unattended services, use a service manager or job scheduler. tmux provides an interactive workspace; it does not automatically restart failed processes or guarantee successful completion.

Close only the intended workspace

Run in your shell
tmux list-windows -t api
tmux list-panes -s -t api
# Only after checking that this disposable session can end:
tmux kill-session -t '=api'

The equals prefix requests an exact session-name match for this target. Stop applications cleanly first where possible. kill-pane, kill-window, kill-session and kill-server have progressively wider effects; there is no general undo.

Pause and test your understanding

Remember in 30 seconds

  • Name sessions by project or purpose.
  • Detach preserves the running workspace, not a durable backup.
  • Switch inside tmux; attach from outside; inspect before killing.
