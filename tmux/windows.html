Module 05 / 18 · about 20 minutes

Windows: organize a project

Give each task a home and move between editor, server, tests and logs without losing context.

By the end, you can…

  • Create, rename, select and reorder windows.
  • Read the status line and use the tree chooser.
  • Understand linked windows and closing behavior.

One window per kind of work

A practical project might have 0:editor, 1:server, 2:tests and 3:logs. Each window can contain one or many panes. Switching windows changes what you see; programs in hidden windows continue running.

0:editorRead and change code
→
1:serverRun the development server
→
2:testsObserve test results
→
3:logsInspect events
Run in your shell
tmux new-window -t api -n tests
tmux new-window -t api -n logs
tmux list-windows -t api
tmux select-window -t api:tests

Named targets make commands readable, but duplicate window names can be ambiguous. Window IDs such as @4 remove ambiguity. Creating a window picks an available index; it does not necessarily append after the highest index if there are gaps.

The default status line marks the current window with *, the last window with -, and a zoomed window with Z. Other flags may signal a bell, activity or a marked pane. Themes may display these differently.

Reorder and avoid surprising renumbering

Run in your shell
tmux move-window -s api:logs -t api:5
tmux swap-window -s api:0 -t api:1
tmux move-window -r -t api

move-window relocates a window; swap-window exchanges two. move-window -r closes index gaps. If the destination is occupied, a move fails unless you explicitly choose behavior that replaces it. Avoid -k here unless destroying the destination is intended.

set -g base-index 1 makes new window indexes start at one. set -g renumber-windows on renumbers after windows close. This is convenient for humans but breaks scripts that assume a task always lives at :2; use names or captured IDs.

A linked window is shared, not duplicated

Run in your shell
tmux link-window -s api:logs -t review:3

This requires a review session and an available destination index. Both sessions now point to the same window and the same panes. Editing or typing in it changes the same programs. unlink-window removes a link; kill-window destroys the window itself and removes it from all linked sessions.

Use linking for a shared monitoring view. Use a new window if you need independent processes. The advanced lesson explains session groups when several shared windows should stay synchronized.

Pause and test your understanding

Remember in 30 seconds

  • Windows organize tasks; hidden programs keep running.
  • Names help navigation; IDs help reliable scripts.
  • Linking shares a live window, so killing it affects every linked session.
