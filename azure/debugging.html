Do not begin by renaming every blob that contains an old case ID. First determine whether the read is deliberately using a saved old-ID address and whether the request ever reaches storage.

Read-only example: inspect saved letter paths

PostgreSQL read-only reference query · run only against an authorized database

SELECT case_id, system_entity_id, file_name,
       meta_data::json ->> 'file_url' AS file_url
FROM investigations_caseartifact
WHERE system_entity_type = 'CASE_LETTER'
ORDER BY case_id DESC
LIMIT 5;

This query returns a few saved paths for filed letters. It does not inspect Azure, transfer files, repair references, or reveal the storage connection string. Confirm the real table, field types, and permissions before using it; these names come from the guide’s model inspection.

Paths may contain case information. Keep diagnostic output appropriately scoped. Never include signed query strings, account keys, or webhook secrets in a report.

“Not found” is a symptom, not a complete diagnosis

EvidenceLikely question to investigateWhat not to assume
Object exists only in a different Azure accountDid key routing choose a fallback or stale configuration?Matching filename means matching object
Saved original exists but extracted output does notWas derived output copied and its returned key saved?Original access recreates extracted text
Application rejects path before making a requestDoes a validator rebuild the current-ID prefix?Azure deleted the object
Grant was valid earlier, access now failsDoes the grant allow this operation and is it still valid?The object must be missing
Customer setting was just changedIs the process still within the routing cache interval?The new setting has already been used everywhere

Worked incident: OCR URL names alpha, demo cannot read it

Suppose the saved URL contains host crimeosbackendalpha... and path private-files/cases/6453/ocr_results/a.txt. The described helper extracts cases/6453/ocr_results/a.txt. Because that is bare, demo’s router chooses demo deployment storage.

Finding the file in alpha does not prove demo opened alpha. Compare the account and container actually selected in demo. If the deployments do not share the same container, the bytes must be made available through a deliberate copy/routing plan; changing the URL host alone does not change this helper’s route.

Predict first: The saved host is correct, but the key is bare. Will replacing only the host repair the described CrimeOS read?

No. That helper ignores the saved host. Determine the key’s route, destination container, and actual object existence. A repair must match the reader’s resolution contract.
