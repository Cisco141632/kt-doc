Words you can explain

A searchable glossary with plain meanings and concrete examples.

Start with the word that is unclear

40 terms

Azure storage account

A named Azure resource that holds storage data, including Blob containers. It is distinct from a CrimeOS customer Account.

Example: lessonstore.blob.core.windows.net

Container

A collection of blobs inside one Azure storage account; it is one coordinate of an object’s address.

Example: private-files

Blob

One stored object containing bytes and associated properties or metadata.

Example: A PDF, a ZIP bundle, or an extracted Markdown file

Blob key / blob name

The full name of a blob inside its container. This is not the secret storage account access key.

Example: delhi/prod/media/case-artifacts/214/run-1/a.pdf

Host / endpoint

The server address used to contact a storage service. The guide’s URL-to-key helper discards a saved host before making its own request.

Example: lessonstore.blob.core.windows.net

Account access key / Shared Key

A broad storage account credential used for Shared Key authorization and account-key signing where enabled.

Example: A secret value; never included in this course

Connection string

Connection settings. The guide uses a string containing an account name and account access key; other connection-string forms exist.

Example: Stored in backend configuration or encrypted customer settings

SAS / signed link

A URL token granting access within a specified resource scope, permissions, and validity interval. It is a credential while usable.

Example: A per-file write grant lasting about 300 seconds in the guide

Permission

An allowed operation, such as reading or writing. One permission does not imply all others.

Example: A write-only grant cannot be used for a download

Expiry

The end of a grant’s validity interval; a fresh grant may be needed after that time.

Example: Case-bundle read grants last about 900 seconds in the guide

Microsoft Entra ID

Azure identity authorization alternative to sharing a storage account key.

Example: An identity authorized to obtain a user delegation key

Managed identity

An Azure-managed identity a supported application can use for identity-based access without storing an account access key.

Example: An Azure-hosted backend identity with the required data access role

User delegation SAS

A SAS signed with a user delegation key obtained through Microsoft Entra authorization, instead of directly using the account access key.

Example: An identity-based SAS option; not the signer described in the CrimeOS snapshot

Deployment

One running copy of the application with its own settings. Different deployments can still share an Azure account.

Example: alpha, gamma, demo, staging, production

Customer Account

A CrimeOS customer organisation represented by the iam Account model.

Example: The guide’s Maharastra customer

Deployment storage

The Azure connection and container configured for the running environment; also the described route fallback.

Example: AZURE_CONNECTION_STRING and AZURE_PRIVATE_CONTAINER

Customer / account storage

Optional customer-specific storage described by a prefix, stage, and encrypted connection string.

Example: Delhi’s prefix delhi and stage prod

Station / jurisdiction

The case’s station, used to find the owning customer account in the guide’s ownership flow.

Example: Case → station → customer → storage configuration

Actor

The user performing an operation; the guide uses the actor’s account as an ownership fallback when needed.

Example: The logged-in user when a case has no station

Prefix

The starting text of a blob name used for matching or grouping. A boundary slash prevents accidental neighboring-ID matches.

Example: case-artifacts/214/

Stage root

The prefix/stage/ start used by the CrimeOS connection router.

Example: delhi/prod/

Media root

The prefix/stage/media start of a normal CrimeOS storage key.

Example: delhi/prod/media

MEDIAFILES_LOCATION

The deployment’s normal media root; owner helpers replace this expected start when routing customer-owned files.

Example: crimeosbackend-demo/demo/media

Routed key

A key whose beginning matches the intended owner’s configured storage root.

Example: delhi/prod/media/case_context_data/214.zip

Bare key

A key lacking a matching configured root; it falls back to deployment storage in the described configuration.

Example: cases/214/ocr_results/a.txt

Routing

The application’s choice of storage connection from the key’s start: deployment root, customer root, or deployment fallback.

Example: connection_for_key(key)

Routing cache

The described in-process cached list of storage origins, with a 60-second lifetime.

Example: A just-edited account root may not be used immediately

Saved path

A full key or URL persisted when a file is created and read back as the file’s address.

Example: CaseArtifact.meta_data.extracted_text_key

Built path

A key recomputed from identifiers or business fields rather than read from a saved object-address field.

Example: An owner-rooted case_context_data/9001.zip

Virtual folder / flat namespace

A folder-like view produced by grouping blob names that share a prefix; slashes are characters in names.

Example: Listing every name beginning case-artifacts/214/

Hierarchical namespace

An Azure Blob/Data Lake configuration supporting directory objects rather than only a flat naming view.

Example: A broader Azure capability, not the guide’s virtual-folder model

CaseArtifact

The guide’s artifact model holding saved original/derived file metadata and request correlation fields.

Example: investigations_caseartifact.meta_data.file_url

file_path_hash

An artifact lookup hash derived from a path; it is not the object key or the file bytes.

Example: A hash on the CaseArtifact row

Storage grant

A backend response giving a permitted file key and signed access URL for a requested case operation.

Example: READ_CASE_BUNDLE or WRITE_DERIVED

Derived file

Output computed from an original, such as extracted text. It is a separate blob with its own address.

Example: complaint_pages_1-3.md

Case bundle

A generated ZIP that packages case context for the AI service.

Example: <media root>/case_context_data/214.zip

keep_urls

The described migration mode preserving saved path text; it does not transfer referenced blob bytes.

Example: Old-ID artifact URLs remain unchanged after an ID offset

ID offset

A transformation that adds an offset to database identifiers during the described migration.

Example: A source case 214 becomes destination case 9001

Sanitiser

Code that validates or transforms untrusted filename input before it is used in a storage key.

Example: Use its returned safe filename rather than raw ../ input

Verified move

Copy to the intended destination, verify completion/correctness, and delete the source only after success.

Example: The guide recommends copy_object_strict before deletion

Three distinctions to keep clear

Customer account ≠ storage accountA CrimeOS customer can have its own Azure storage, or use deployment storage.
Blob key ≠ account access keyThe blob key is a name. The account access key is a secret.
Saved path ≠ bytesA database value describes where to look. It does not contain the stored PDF.
