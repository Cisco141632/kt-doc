Where the CrimeOS examples come from

The supplied azure-storage-learning-guide.html, dated 2026-11-06, is the source for the CrimeOS-specific lessons. Its stated basis is the demo account-storage branch and the audits described in that guide. This course preserves that snapshot; it is not a new audit of every active CrimeOS branch.

The original guide's glossary becomes the glossary; Parts 1–11 become the eleven lessons; Part 12 becomes the assessment. The seven labs let you experiment with those same rules. Real storage names appearing in lesson examples are quoted from the guide. Lab names and credentials are fictional.

Examples of current-code checks before changing a service: confirm the routing helper and its cache behavior, the model's actual table name, the storage-grants allowlist, and the migration tool's active branch. The code map tells you where the guide found these behaviors.

After this course: operating the storage account

This learning path covers Blob Storage and the complete supplied CrimeOS guide. Azure also has storage services and operating choices beyond that guide. Continue with these topics when you need them:

  • Access tiers: compare frequent reads with cooler data and archive rehydration before choosing a tier.
  • Redundancy: understand which failures replication protects against; replication is different from protection against an accidental delete.
  • Data protection: plan versioning, soft delete and recovery for the account's supported configuration.
  • Lifecycle policies: manage aging data deliberately; review delete actions before enabling them.
  • Network access and CORS: browser access can involve network and origin checks in addition to authorization.
