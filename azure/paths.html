Saved paths and rebuilt paths behave differently

A saved address versus a recipe for an address

Saved pathDatabase records the key or URL created when the file was written
→
Read laterUse that saved value, even if it contains an old ID
Built pathCode combines the current inputs into a key
→
Read or regenerateUse the resulting key; generation requires an explicit workflow
QuestionSaved pathBuilt path
What does the database hold?The file’s full key or URLNo saved object address for that file; it may hold generation status
How is the key obtained?Read the saved valueBuild it from case or business identifiers
What if the case ID changes?The saved old-ID name stays the sameA DB-ID-based recipe computes a new name
Can missing bytes reappear?Not from the path aloneOnly if a generation workflow recreates them from available inputs

“Built” does not mean Azure automatically regenerates a missing file. It means the application can know its name without a saved path. Whether regeneration runs, and which data it needs, depends on the workflow.

What the CrimeOS URL reader keeps

Worked example · illustrative, no Azure request is sent

Saved URL:
https://crimeosbackendalpha.blob.core.windows.net/private-files/cases/6453/ocr_results/a.txt

get_object_key_from_file_url(...) keeps:
cases/6453/ocr_results/a.txt

Then the current environment selects:
connection_for_key(key) + its own container + key
Saved URL componentUsed by the described reader?What happens
HostNoDiscarded when extracting the object key
First path segment: containerNoRemoved; the reading environment opens its configured container
Remaining path: keyYesIts beginning is used for connection routing
This is application behavior

A client opening an ordinary Azure URL directly contacts that URL’s host. This lesson describes a CrimeOS helper that parses a saved URL and then makes a different request through the storage adapter. Do not generalize “the host is ignored” to Azure itself.

Keep saved addresses stable on reads

Suppose an upload was saved at delhi/prod/media/case-artifacts/214/run-1/a.pdf. A migration gives the case ID 9001. The saved address can still find the old-ID object if the route, container, and object remain correct. Constructing .../9001/... on read asks for another object.

A validator can also break the valid old path by insisting that it begins with a prefix rebuilt from the new ID. Review the reader, writer, and validator together. If a path must be rewritten, treat that as an explicit migration involving both bytes and references.

Predict first: The database still holds an upload’s old-ID URL and the file exists. Must its filename be changed to the new case ID?

Not merely to read it. Read the saved path and route its key correctly. Renaming without updating all references creates another consistency problem. A current-ID validator may still need correction.

Remember in 30 seconds

  • Saved files are read using their stored address; built files use a recipe.
  • The CrimeOS URL-to-key helper discards the saved host and container before routing.
  • An old ID in a saved key can be valid; a newly built validator can wrongly reject it.
