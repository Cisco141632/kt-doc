Make one change, then explain the result

These seven labs collect the interactive parts of the course. Use them in order, or return to the concept you need. Each lab runs in your browser. Its reset button resets the experiment; your completed-lab record is managed separately.

Seven experiments · no Azure account required

01. A file has three coordinates

Create a file, switch the container, and list a prefix. Explain why the same key in another container is a different blob.

Review the lesson → Ready to explore

02. Give access for a limited time

Try a read using a write-only grant, then advance the simulated clock beyond expiry. Predict which requests fail before you try them.

Review the lesson → Ready to explore

03. Where does this key go?

Compare a customer-rooted key, a deployment key and a bare key. Then introduce a conflicting root and explain the fallback.

Review the lesson → Ready to explore

04. Keep the saved path or rebuild it?

Change case 214 to 9001. Compare reading a saved upload with rebuilding a bundle. Try a validator based on the new ID.

Review the lesson → Ready to explore

05. Follow complaint.pdf

Walk through the upload and AI extraction. At each step identify who chooses the key, who transfers the bytes, and what the database remembers.

Review the lesson → Ready to explore

06. Move the rows and the files

Copy database rows without blobs, then add the blobs and matching routing configuration. Compare saved artifacts with rebuilt bundles and bare keys.

Review the lesson → Ready to explore

07. Find the cause, then fix it

Inspect the evidence in each incident. Distinguish routing, missing bytes, expired access and an application validator before choosing a fix.

Review the lesson → Ready to explore

Explain a new feature before coding it

A case needs a generated PDF that must still open after a database migration. Write down the owner, the key helper, the saved column, the reader and the migration plan before opening the answer.

Compare your design with a worked answer

Resolve the case's owning customer. Build a key under MEDIAFILES_LOCATION, pass it through key_for_case, write using the routed storage adapter, and save the returned key or URL. Read the saved value later. A migration must preserve that key, copy the bytes separately, and configure the same account root in the destination. Avoid checking the saved path against a path rebuilt with the new case ID. Test both a customer with its own storage and one that uses deployment storage.

Remember in 30 seconds

  • Change one variable at a time and trace its effect.
