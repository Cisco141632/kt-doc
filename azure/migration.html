Imagine an index card saying “file A is in cupboard C.” Copying that card gives you the address, not the file. In the same way, a database dump can contain file_url while containing none of the referenced PDF bytes.

The guide’s MH-to-demo migration contract

The guide describes branch feature/demo/mh-final-migration-20261104 and tool directory data_loading/mh_migration/. Its default keep_urls behavior leaves saved paths unchanged. Referenced files are expected to be copied separately with identical keys.

For the MH customer in demo, the reviewed mapping sets prefix crimeos-backend-maha-police-prod and stage mahapolice-prod. A preserved key beginning with that root can then route through the customer’s configured storage connection. The mapping is recorded in iam/constants/account_storage_origins.py.

The tool excludes cases.CaseAIData. The destination therefore does not inherit a bundle row pointing at an old generated ZIP; the bundle-generation workflow can build one under the new case ID. This design is different from preserving an original upload’s saved key.

One old ID can still be a valid saved address

Worked example · illustrative, no Azure request is sent

Before move:
  Case ID: 214
  Saved upload: delhi/prod/media/case-artifacts/214/run-1/a.pdf

After move with keep_urls:
  Case ID: 9001
  Saved upload: delhi/prod/media/case-artifacts/214/run-1/a.pdf
  Built bundle: delhi/prod/media/case_context_data/9001.zip

Wrong read-time guard:
  require saved upload starts with .../case-artifacts/9001/

The guide calls out intake, refund/defreeze, and draft-read checks that build a prefix from the current ID. Such a check can reject a valid preserved file. Do not “fix” it by constructing an address that was never written; inspect the persisted reference and ownership validation.

Predict first: Case 214 becomes 9001. The saved upload exists and routes correctly. Is the old 214 segment by itself evidence of a broken migration?

No. keep_urls intentionally preserves the saved object address. Check object existence, routing, and any validator. A built bundle can use 9001 while the preserved upload continues to use 214.

A move must protect the source until verification

The guide found an application move_object path that could delete the source after an unverified or failed copy. Its rule is copy, verify completion and correctness, then delete. It recommends copy_object_strict rather than the error-hiding copy_object path.

Check the actual helper’s contract before using it in a new tool. A requested or accepted copy is not evidence that the destination bytes are complete. Do not turn a missing destination into loss of the only source copy.
