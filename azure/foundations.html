Find a file: account, container, blob

Start with a building, a cupboard, and a file. Then learn the three coordinates that identify a blob and why a slash can be part of its name.

By the end, you can…

  • Identify a storage account, container, blob, and blob key.
  • Read a standard Blob Storage URL without confusing a path with permission.
  • Explain why the same key can identify different files in different places.

Begin with something familiar

You have a PDF on your laptop. A server and an AI service also need to open it. Azure Blob Storage gives the application a place to keep those bytes and an API for reading and writing them. A blob is one stored object: a PDF, image, ZIP, or text file.

Storage accountThe building · a named Azure storage resource
→
ContainerA cupboard · a collection of blobs
→
BlobThe file · bytes stored under one name

A storage account is a resource in Azure. A container sits inside that resource; a blob sits inside the container. These are different levels. Creating a database row does not create a blob, and creating a blob does not automatically create a row.

Every file needs three coordinates

Worked example · illustrative, no Azure request is sent

Storage account: lessonstore
Container:       private-files
Key:             cases/214/complaint.pdf

https://lessonstore.blob.core.windows.net/private-files/cases/214/complaint.pdf
PieceWhat it selectsExample
Storage account / hostWhich Azure storage resourcelessonstore.blob.core.windows.net
ContainerWhich collection inside that resourceprivate-files
Key / blob nameWhich object inside that collectioncases/214/complaint.pdf

The storage account name is globally unique in Azure’s storage account namespace and appears in its standard service address. Knowing only cases/214/complaint.pdf is like knowing a file label without knowing the building or cupboard. The identical key in two accounts or two containers identifies two independent blobs. A valid address also does not grant permission to read a private blob; access comes next.

Predict first: Two accounts both contain cases/214/complaint.pdf. Are these one shared PDF?

No. Compare all three coordinates. The account is different, so these are separate stored objects even if their names and bytes happen to match.

A folder view can be a view of names

In a flat namespace, case-artifacts/214/run1/derived/x.md is one blob name. The slash characters help people group names; they do not create directory objects. Listing a virtual folder means listing names beginning with its prefix.

Worked example · illustrative, no Azure request is sent

Prefix: case-artifacts/214/

Included: case-artifacts/214/run1/complaint.pdf
Included: case-artifacts/214/run1/derived/x.md
Excluded: case-artifacts/2140/run1/complaint.pdf
Keep the boundary slash

case-artifacts/214/ is a more precise prefix than case-artifacts/214: the latter also begins the name for case 2140.

The guide describes this flat naming model. Azure also supports a hierarchical namespace with directory objects, so “there are no real folders” is a statement about this system’s naming model, not every Azure configuration. Microsoft: hierarchical namespace.

What reading and writing actually mean

OperationWhat changesQuestion to ask
Read / downloadReturns bytes; the blob normally stays where it isDo I have the right coordinates and permission?
Write / uploadStores bytes at a keyIs overwriting this exact object allowed?
List a prefixReturns matching namesDoes the prefix include the account root and a boundary slash?
DeleteRemoves the addressed object, subject to enabled protection featuresHave I verified which account, container, and key this selects?

An overwrite-enabled write to an existing key updates that object rather than making a second object with the same name. Whether an API call allows overwrite, requires conditions, or retains an older version depends on the operation and configuration. Do not assume that a new database ID protects an existing blob.

What this course means by Azure Storage

Azure Storage also offers file shares, queues, and tables. This learning path concentrates on Blob Storage, because CrimeOS documents, OCR text, case bundles, and derived AI files use blobs. You do not need to learn every Azure service before you can follow one PDF.

For the basic resource model, see Microsoft’s Blob Storage introduction. Real names in later CrimeOS examples are labels from the guide; all browser exercises are simulations and use no credentials.

Remember in 30 seconds

  • A blob is found by storage account + container + exact key.
  • In the guide’s flat namespace, slashes are part of the blob name.
  • A URL tells you an address; it does not by itself authorize a private read.
