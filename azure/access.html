Open a file without sharing the master key

Understand account-key connection strings, signed links, permissions, expiry, and why the browser and AI receive narrow grants.

By the end, you can…

  • Distinguish a blob name from a secret account access key.
  • Predict access from a signed link’s resource, permissions, and validity interval.

The word key has two different meanings

A blob key is a name such as cases/214/complaint.pdf. An account access key is a credential. Confusing them makes discussions about “sending the key” dangerous: the AI can receive a blob name as an identifier, but it must not receive the storage account’s secret access key.

ItemMeaningTreat it as a credential?
Blob keyName inside a containerIt may reveal sensitive context, but it is not authorization by itself
Account-key connection stringConnection settings containing the account name and secret access keyYes; broad account access where Shared Key is allowed
Signed link / SAS URLResource URL with a token granting specified accessYes; anyone holding it can use its granted access

Give the visitor a temporary permission slip

BackendHolds the authorized signing credential
→
Signed linkOne resource + allowed action + expiry
→
Browser or AIUses the link directly with Azure

A shared access signature (SAS) delegates access. Its scope, permissions, and times are part of what is signed. Merely changing a read flag to a write flag in an existing URL does not grant write access: the signature would no longer match. The backend must issue the appropriate grant.

In the guide’s implementation, ordinary read links last about 300 seconds, case-bundle read links about 900 seconds, and write links about 300 seconds. These are application defaults, not Azure-wide limits.

Check three things before predicting success

CheckExampleExpected consequence
ResourceA grant for complaint.pdf is used for another blobThe other blob is outside the grant
PermissionA write-only grant is used to downloadThe operation is not permitted
ValidityA five-minute grant is used after its expiryThe grant is no longer valid

These checks describe the token. Real requests can also fail because the blob is missing, network access is blocked, or the request does not meet Azure’s other conditions. Expiry is a ceiling on a grant, not a promise that every request before expiry succeeds.

Predict first: The AI has a valid write-only link for a text file. Can it read the PDF next to that file?

No. The grant covers a specified resource and permissions. A write grant to the text file is not a read grant to the original PDF. The AI asks the backend for the access it needs.

What the guide’s signer needs

The guide’s backend signs using the selected storage account’s account key, obtained from its connection string. A connection string containing only an existing SAS token does not supply that signer with an account key, so it cannot use that implementation to mint new account-key-signed links.

Azure has more than one authorization method

Account-key signing describes this CrimeOS snapshot. Azure also supports Microsoft Entra authorization, managed identities, and user delegation SAS. A SAS can cover broader resources and multiple permissions; the guide deliberately issues narrow per-file grants. Microsoft: SAS types and scopes.

For new Azure designs, Microsoft recommends using Entra credentials and managed identities where possible. That broader guidance does not mean the audited branch already uses them. Microsoft: account keys and identity guidance.

Keep credentials on the correct side of the boundary

The backend holds the deployment connection string in configuration and customer connection strings encrypted in the database. The browser and AI get the necessary signed links. Neither needs the broad secret to upload one document.

Do not print a connection string, webhook secret, or signed URL in logs, examples, screenshots, or support messages. Expiry reduces exposure but does not make a signed link public information. If a link expires during a workflow, request a fresh grant through the backend rather than expanding the AI’s privileges.
