Find the owner before choosing storage

Separate deployments, Azure storage accounts, and CrimeOS customer accounts. Follow a case through its station to its owning customer.

On this pageA deployment is a running copy of the productAn Azure account is not a customer accountThe case’s station is the starting pointThe guide’s alpha and gamma exampleWhy the feature existsFollow the resulting routeCheck what you understand

By the end, you can…

  • Explain the two meanings of account.
  • Trace case ownership without substituting the viewing user.
  • Understand deployment storage, optional customer storage, and shared-account collision risks.

A deployment is a running copy of the product

Alpha, gamma, demo, staging, and production are deployment names. Each deployment has storage settings. “Storage configured for each deployment” does not guarantee that every deployment has a separate Azure storage account.

An Azure account is not a customer account

QuestionAzure storage accountCrimeOS customer Account
What is it?A named storage resource in AzureA product customer such as a police organisation
Where is it defined?Azureiam app, Account model
What does it contain?Containers and blobsCustomer information and optional storage settings
How are they connected?A credential opens the Azure resourcestorage_prefix, storage_stage, and an encrypted connection string describe customer storage

When the customer has no dedicated storage configured, its files use the deployment storage. When configured, correctly rooted keys can route to its own storage. Adding customer storage settings alone does not transform every existing bare key.

The case’s station is the starting point

Case 9001The case whose file is being handled
→
Station / jurisdictionThe case’s station
→
Customer AccountThe station’s owning customer
→
Storage settingsThat owner’s configured root and connection

The guide’s ownership service first follows the case’s station to its customer account. If the case has no station, it uses the actor’s account when available. If neither can be found, it warns and uses deployment storage. A person merely opening another customer’s case does not become the owner of its files.

Predict first: A Delhi user opens a case whose station belongs to Maharastra. Which customer should own the new case artifact?

Maharastra. Follow the case’s station first. The viewing user is a fallback when ownership cannot be obtained through the case, not a replacement for an existing case owner.

The guide’s alpha and gamma example

The guide reports a gamma row with host crimeosbackendalpha.blob.core.windows.net, container private-files, and a key beginning crimeosbackend-gamma/gamma/media/. It describes alpha and gamma sharing that account and container while separating normal files with their key prefixes.

Worked example · illustrative, no Azure request is sent

Same Azure account and container:
  crimeosbackend-alpha/alpha/media/case-artifacts/214/a.pdf
  crimeosbackend-gamma/gamma/media/case-artifacts/214/a.pdf

An unprefixed name could collide:
  cases/214/ocr_results/a.txt
Naming separation depends on using the names

If two environments share a container and both write the same bare key, they address the same blob. Separate prefixes prevent that collision only for code that actually includes them.

A prefix is also not an independent Azure credential boundary. CrimeOS must still enforce who can request access, choose the right owner, and issue appropriate grants.

Why the feature exists

The account-specific storage feature lets a customer keep its case data in its own Azure storage account. The guide associates it with feature/*/account-storage-origin-20261030. The root has a routing purpose: it makes the file’s owning storage identifiable from the key.

The ownership implementation is mapped to common/services/account_storage_routing.py and common/adapters/account_service_ownership.py. The next lesson connects this owner lookup to the key helpers and router.

Remember in 30 seconds

  • A deployment, an Azure storage account, and a customer Account are different things.
  • Find a case owner through its station; use the actor only as the described fallback.
  • Customer settings need correctly rooted keys to route files to customer storage.
