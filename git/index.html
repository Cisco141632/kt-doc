Module 01 / 23 · about 15 minutes

Git, explained one picture at a time.

Start with a school project and discover what Git does, why it matters, and how GitHub helps people work together. Build confidence with pictures, hands-on practice and short recall sessions.

By the end, you can…

  • Explain Git and GitHub in different terms.
  • Choose a learning route and practise in disposable repositories.
  • Know the questions to ask before changing shared history.

Start with a familiar problem

You are making a school project. Yesterday it was correct; today you accidentally deleted a useful paragraph. A friend has a different copy. Which version should you keep, and how can you combine your work? Git helps you keep a clear history of recorded versions. Start with the illustrated beginner lesson, then build up to real development problems.

Git is a distributed version-control system. It keeps a history of project versions you deliberately record on your computer. GitHub hosts repositories and adds pull requests, code review, issues, permissions, rules, automation and collaboration. A local commit is not automatically uploaded, reviewed, approved or deployed.

The five questions

Which repository and branch am I on? Is the work committed or uncommitted? Is this history already shared? Which local or remote reference will move? What evidence and recovery point do I have?

How to use these documents

Core commands use modern Git, including switch and restore (Git 2.23+). Labs also use git init -b (2.28+). Check git --version and the installed manual. GitHub capabilities depend on repository visibility, plan, organization policy and GitHub Enterprise version. Official sources are linked near the relevant explanations and collected in the reference.

The browser exercises are simulations: they do not access or modify any repository. The real labs use newly created local repositories and local bare remotes, so no GitHub account or access token is needed. Do not run a destructive practice command in a work repository.

Command placeholders such as COMMIT, OLD_BASE and feature must be replaced with inspected values in your real project. Examples use POSIX shell syntax; use Git Bash or WSL on Windows for those snippets. There are no real credentials in these documents.

This is a complete practical learning path, not a claim to list every Git plumbing flag or every GitHub product. Advanced topics point to their primary manuals. Learning progress is local to this browser and can be exported on the recap page.

Remember in 30 seconds

  • Git records snapshots and ancestry; GitHub adds collaboration and policy.
  • Inspect state and shared ownership before changing history.
  • Practise risky operations only in a disposable repository.
