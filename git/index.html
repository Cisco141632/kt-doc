Learn Git and GitHub, step by step

Start with one file. See what each command changes, learn how Git keeps your work, and practise fixing mistakes.

Need help with HEAD, index, staging, or diff?
Your file
What you are editing now. Git calls the project files the working tree.
Staging area = index
The file content you chose for the next commit. These are two names for one place.
HEAD
Tells Git which saved commit you are using, usually through your current branch.
Diff
A comparison showing added and removed lines between two versions.
Watch these change with one file →

By the end, you can…

  • Know where to start, even if you have never used Git.
  • Learn with one small example at a time.
  • Find the lesson and fix you need when something goes wrong.

Understand what just happened

You save a file, change it, and wish you could get the earlier version back. A friend changes another part of the project. You need a way to keep useful versions, compare changes, and combine your work.

Before
Without a clear history
notes-final.txt
notes-final-2.txt
Which one had the right change?
→Save useful versions with Git
After
With Git
A · Write the first note
B · Add a title
C · Fix the date
Read or compare each saved version.

Git keeps the versions you choose to save on your computer. GitHub is a website where people share Git projects, discuss changes, and review work. You can learn local Git before creating a GitHub account.

Examples use a Linux or macOS shell; Windows learners can use Git Bash. The first setup lesson explains how to check Git is installed. The practice-folder builder also needs Python 3. Commands using names such as COMMIT or REPOSITORY_URL explain what to replace before running them.

Pictures and browser exercises do not run Git or change your projects. Real labs use new practice folders and a shared repository stored locally. Progress stays in this browser; you can back it up on the review page.

What to remember

  • Start with the story, then follow a single file through add and commit.
  • Use pictures to predict the result before trying a command.
  • When a command fails, read the message and check the state before changing more.
