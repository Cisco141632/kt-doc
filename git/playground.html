Module 19 / 23 · about 35 minutes

Visual history and decision labs

Step through history changes, resolve a three-way conflict, simulate a lease race and diagnose a permissions gate.

By the end, you can…

  • Predict merge, rebase, squash, revert, reset and fetch effects.
  • Resolve combined intent instead of accepting a whole side.
  • Explain why a push or a permission decision is accepted or rejected.

A model you can inspect

These tools are simulations. They do not run Git, access a repository, authenticate to GitHub or change server settings. Labels such as A, B and C stand for commit IDs; actual objects have content-derived IDs. The model intentionally focuses on a few important rules. Use the real labs and full manuals for command behavior.

Remember in 30 seconds

  • Changing a graph label can change reachability without erasing every object.
  • A valid resolution preserves the stated requirements, not just syntax.
  • A lease and a repository role each solve only part of a larger decision.
