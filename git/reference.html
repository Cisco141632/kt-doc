Find a command or a word

Look up a task and check what its command changes. Find plain meanings for Git words and links to the full manuals.

Need help with HEAD, index, staging, or diff?
Your file
What you are editing now. Git calls the project files the working tree.
Staging area = index
The file content you chose for the next commit. These are two names for one place.
HEAD
Tells Git which saved commit you are using, usually through your current branch.
Diff
A comparison showing added and removed lines between two versions.

What do you want to do?

These are separate examples, not a script. Replace path, COMMIT, TARGET, and example branch names with the actual file or ID you checked. Read the related lesson before replacing files or shared commits.

Your taskCommandWhat to remember
See what is saved and what is waitinggit statusRead the branch, paused operation, chosen changes, and edits still in your files.
Read edits not yet chosen for a commitgit diffCompares staging with your file. New untracked file contents are not shown.
Read changes chosen for the next commitgit diff --stagedCompares the current saved commit with staging.
Choose only some changed linesgit add -p -- pathReplace path with a file. Read each group of lines before choosing it.
Save the chosen changesgit commit -m 'Describe behavior'Commit saves staging. Later file edits are not chosen automatically.
Create and enter a branchgit switch -c feature/nameCheck the starting commit and waiting edits first.
Download shared history without combining itgit fetch originYour current branch and files stay as they are.
Fetch and update only if no separate work needs combininggit pull --ff-onlyIf refused, read both sides before choosing merge or rebase.
See which remote branch each local branch followsgit branch -vvAhead/behind counts use last-known positions. Fetch for a newer view.
Send a branch and remember its destinationgit push -u origin featureCheck the remote address and branch name first.
See a picture of saved historygit log --graph --oneline --decorate --allShows history reached through locally known names. Fetch if the server matters.
Find the shared starting commitgit merge-base main featureA complex history can have more than one suitable common base.
Move forward without a new merge commitgit merge --ff-only featureYour current commit must be in feature’s earlier history.
Combine with a merge commitgit merge --no-ff featureRecords both branches as parents when work needs combining.
Choose one combined change from a branchgit merge --squash featureInspect and commit separately. Feature is not recorded as a second parent.
List files still needing a conflict choicegit diff --name-only --diff-filter=UNo output means none are listed. It does not prove the program works.
List the stored conflict versionsgit ls-files -uNumber 1 is base, 2 is ours, 3 is theirs. Some may be absent.
Read the conflict’s starting filegit show :1:pathReplace path with the actual file. A newly added file may have no base.
Read the conflict side called oursgit show :2:pathIn rebase this is the new starting work plus changes already reapplied.
Read the conflict side called theirsgit show :3:pathIn rebase this is the original commit being applied now.
Finish a merge after fixing its filesgit merge --continueAdd the resolved files, inspect, and test first.
Stop a merge in progressgit merge --abortUnsaved unrelated work can make an exact return harder.
Apply your changes after the fetched maingit rebase origin/mainUse a clean branch and keep a backup name for the old commits.
Read the change rebase is applying nowgit rebase --show-current-patchUseful when rebase pauses at a conflict.
Continue a rebase after fixing filesgit rebase --continueAdd, inspect, and test. Another commit can conflict next.
Stop rebase and return to its starting stategit rebase --abortDifferent from --quit, which leaves the current files and commit position.
Compare old and new lists of changesgit range-diff OLD_BASE..old-tip NEW_BASE..new-tipReplace the example names with checked IDs or branches. Read missing/changed entries.
Replace only the exact server position you checkedgit push --force-with-lease=refs/heads/feature:EXPECTED origin HEAD:refs/heads/featureEXPECTED must be the reviewed full ID. This still needs permission and agreement.
Send your current commit to an exact server branchgit push origin HEAD:refs/heads/featureHEAD is the source. The name after the colon is the server destination.
Find where a local branch used to pointgit reflog --date=isoA local movement list that can expire. It does not save every file edit.
Keep a found commit under a rescue namegit branch rescue/work COMMITInspect COMMIT first. A branch keeps commits, not uncommitted file text.
Undo a shared change with a new correctiongit revert COMMITReverses that change in current files. It may conflict; test afterward.
Move a private branch, keeping staging and filesgit reset --soft TARGETCheck TARGET and keep the old commit under a backup name.
Move a private branch, unstage changes, keep filesgit reset --mixed TARGETStaging becomes TARGET’s version. Your files stay. Reset with a file path behaves differently.
Replace branch, staging, and tracked filesgit reset --hard TARGETCan discard work and remove untracked paths in the way. Keep wanted files first.
Remove changes from the next commit, keep your filegit restore --staged -- pathRestores staging for that file from the current saved commit by default.
Throw away edits not yet stagedgit restore -- pathOverwrites the file from staging. Save wanted edits elsewhere first.
Save unfinished tracked and new files temporarilygit stash push -u -m 'Explain WIP'-u includes untracked files but not ignored files.
Read a temporary saved changegit stash show -p 'stash@{0}'Inspect before applying or dropping it. Number 0 means newest.
Read one file’s earlier historygit log --follow -- pathAttempts to follow earlier names of one path.
Find the commit that last changed selected linesgit blame -L 20,40 -- pathRead the commit and context. Formatting can affect who appears here.
Find commits that changed the count of some textgit log -S 'text' -- pathUse -G for a pattern search in added or removed lines.
Use a test to find the first bad commitgit bisect run ./test-regression.shExit 0 means good; 125 means cannot test. Finish with git bisect reset.
Copy one fix into the current branchgit cherry-pick -x COMMITNew context usually makes a new ID. Check whether earlier changes are needed.
Open a second working foldergit worktree add ../hotfix -b hotfix mainFiles, staging, and HEAD are separate. Commit storage and branch names are shared.
Name a release commit with a messagegit tag -a v1.2.0 -m 'Release 1.2.0'Check the chosen commit/version. Push the intended tag explicitly.
Find the ignore rule for a filegit check-ignore -v -- pathIgnore rules do not stop tracking a file already added.
Find where your commit-email setting came fromgit config --show-origin --get user.emailLocal settings can override global ones. Email does not sign you into GitHub.

Words explained in plain English

Return when a word gets in the way. HEAD, index, staging, and diff are shown with one file here.

Commit
A project version you chose to save, with a message, ID, and links to earlier commits.
Staging area / index
The file versions chosen for the next commit. These are two names for the same place.
Working tree
The project files currently in your working folder. Your editor changes these files.
HEAD
Tells Git which commit you are using, usually by naming your current branch.
Diff / patch
A comparison of two versions. Removed lines start with -; added lines start with +.
Branch
A name pointing to a commit. It moves when you make new commits on it.
Parent / ancestry
A parent is an earlier commit named by another commit. Ancestry means these earlier-commit links.
Snapshot / tree / blob
Snapshot means a saved project state. A tree records file names and their stored contents. A blob stores a file’s content.
Repository / repo
A project together with its Git history and settings. Repo is just the short form.
Local
On your computer.
Remote / origin
A remote is a saved address for another repository. Origin is its usual name.
Reference / ref / tip
A reference is a saved name pointing to a commit. Ref is its short form. Tip means the commit at the end of a branch.
Remote-tracking reference
Your local record of a remote branch’s last-known commit, such as origin/main.
Upstream
The remote branch your local branch follows. Also a common remote name for a fork’s original project.
Clone / fork
Clone is a local copy with history. Fork is a GitHub copy under another owner, where allowed.
Fetch / pull / push
Fetch downloads shared history. Pull fetches and uses it on your branch. Push sends your commits.
Merge / base
Merge combines work. Base is the shared starting version used to see what each side changed.
Fast-forward / diverged
Fast-forward moves a branch to an existing later commit. Diverged means both sides made separate new commits.
Conflict / ours / theirs
A conflict needs your choice of final content. Ours/theirs depend on the operation; rebase uses different sides from an ordinary merge.
Rebase / replay
Apply selected changes again after a new starting commit, usually making new IDs. Replay means apply again.
Squash
Combine changes into one commit, without recording the source branch as a second parent.
Lease
Replace a remote branch only if it is still at the commit you expect.
Revert / reset / restore
Revert adds a correction. Reset can move a branch and change staging/files. Restore changes staging or files without moving the branch.
Reflog / stash
Reflog records local branch movements. Stash temporarily saves unfinished edits.
Pull request / base / head
A GitHub proposal to combine work. Base receives the changes; head holds them. PR head is different from Git HEAD.
Authentication / authorization
Authentication proves who you are. Authorization decides what that person or credential may do.
Credential / token / scope
A credential proves an identity. A token is a secret credential with limits. Scope names a set of allowed actions.
Ruleset / bypass
A group of rules for selected branches or tags. Bypass is a specifically allowed exception.
CODEOWNERS
A file mapping paths to reviewers. A separate rule makes their approval required.
Workflow / job / CI
A workflow defines automated jobs. A job runs steps such as tests. CI means running checks as changes are made.
Signature
A checkable link between an exact commit or tag and a signing key. It does not prove the code works.
Regression / bisect
A regression worked before but fails now. Bisect narrows a tested good-to-bad commit range.
Cherry-pick / worktree / rerere
Copy a selected change; open another working folder; remember and reuse a conflict fix. The extra-tools lesson explains each with examples.
