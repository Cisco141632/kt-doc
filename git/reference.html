Commands, glossary & trusted references

Find the command by intent, understand its scope and continue into official Git and GitHub documentation.

By the end, you can…

  • Use the command sheet without ignoring context.
  • Keep common terms distinct.
  • Check version- and plan-specific details in primary sources.

See the current replayed patchgit rebase --show-current-patchUseful when a rebase stops at a conflict.
Continue a resolved rebase stepgit rebase --continueLater commits may conflict again.

Compare old and new patch seriesgit range-diff OLD_BASE..old-tip NEW_BASE..new-tipUse correct boundaries; inspect unmatched and changed patches.
Pin a lease to an expected remote tipgit push --force-with-lease=refs/heads/feature:EXPECTED origin HEAD:refs/heads/featureReplace EXPECTED with the reviewed full ID. Server rules still apply.
Push to an explicit branch destinationgit push origin HEAD:refs/heads/featureExplicit destination reduces ambiguity; it does not validate content.
Find local reference movementsgit reflog --date=isoLocal and expiring, not a server-wide durable backup.

Undo a public change with new historygit revert COMMITAn inverse patch can conflict and needs tests.

Terms that are easy to confuse

Commit
An immutable snapshot reference plus parents, metadata and message.
Branch
A movable reference to a commit; not a copied directory.
HEAD
The current checkout reference, usually symbolic to a branch, sometimes directly to a commit.
Index
The staged snapshot and, during conflicts, unmerged entries.
Working tree
Files currently checked out on disk.
Remote
A named configuration for another repository’s URL and fetch/push behavior.
Remote-tracking reference
Your local cached observation of a remote ref, such as origin/main.
Upstream
A configured tracking relationship; also a conventional name for a fork’s parent remote.
Merge base
A best common ancestor used to understand divergence; complex histories may have several.
Fast-forward
Moving a ref to a descendant without needing a new merge commit.
Three-way merge
Combining changes using a base and two side snapshots.
Rebase
Replaying selected changes onto another base, normally creating replacement commits.
Lease
An expected-value condition on a remote ref update, not a content-preservation guarantee.
Revert
A new inverse change that preserves prior ancestry.
Reset
A family of operations that can move a tip and/or adjust index/working state, depending on mode and path form.
Reflog
A local record of ref movements, with expiration and retention limits.
Pull request
A hosted proposal to integrate one branch’s work into another with discussion and review.
Authentication
Establishing the identity making the request.
Authorization
Determining which operations that identity and credential may perform.
Ruleset
A set of server-side repository/branch/tag constraints with targets, enforcement and bypass behavior.
CODEOWNERS
A path-to-owner review-routing file; required enforcement is configured separately.
Signature
Cryptographic evidence about an object and signing key; not a code-quality guarantee.

Start with these primary references

References were reviewed in October 2026. Git commands vary with version; GitHub features vary with plan, visibility, organization policy and Enterprise version. Use your installed git help COMMAND for local behavior.

  • Pro Git, the official online book — the best continuous companion for fundamentals, branching and internals.
  • Git command reference — complete command options, edge cases and version histories.
  • git merge, git rebase, git push — integration and lease semantics.
  • git reflog, git reset, git revert — recovery and undo boundaries.
  • git bisect and git range-diff — regression investigation and patch-series review.
  • GitHub pull request merge methods — platform-specific integration behavior.
  • GitHub organization repository roles — full capability matrix.
  • GitHub access tokens — scopes, selection, approval and current support limits.
  • Rulesets, creation steps, rule semantics — targets, enforcement and plan availability.
  • CODEOWNERS — matching, ownership and review requirements.
  • GITHUB_TOKEN permissions and secure use of Actions — automation trust boundaries.
  • Removing sensitive data — revocation, cleanup limitations and coordinated recovery.

These original lessons synthesize practical workflows; the linked manuals are the source of complete version-specific flags and platform behavior. Start with Pro Git for a continuous narrative, then use the command manual for a precise edge case.

Remember in 30 seconds

  • Choose commands by intent and state, not by how often you have seen them.
  • Official references resolve version- and policy-specific details.
  • A strong workflow preserves evidence, shared intent and a recovery path.
