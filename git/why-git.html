What is Git, and why do we need it?

Start with a school project. Learn why saving useful versions matters, how Git helps a team, and how GitHub fits in. No coding knowledge needed.

Need help with HEAD, index, staging, or diff?
Your file
What you are editing now. Git calls the project files the working tree.
Staging area = index
The file content you chose for the next commit. These are two names for one place.
HEAD
Tells Git which saved commit you are using, usually through your current branch.
Diff
A comparison showing added and removed lines between two versions.

By the end, you can…

  • Explain Git in your own words.
  • Save a version, make a mistake and recover earlier content in a visual model.
  • Tell Git apart from GitHub, autosave and a backup.

Imagine you are making a science-project website

01

Monday: a good start

You write a title and two facts about the solar system.

Our solar systemEight planets orbit the Sun.Earth is our home.
02

Tuesday: an accidental edit

You replace the correct fact while trying a new idea. You want the earlier work back.

Our solar systemEight planets orbit the Sun.Two planets orbit the Sun.
03

Wednesday: a teammate joins

Your friend improves the title while you add a fact. How do you keep both changes?

Our amazing solar systemEight planets orbit the Sun.Earth is our home.The Sun is a star.

Renaming files to project-final, project-final-2 and project-really-final quickly becomes confusing. You need a clear record of useful versions and a way to compare changes.

Git keeps the project versions you choose to save

The idea in one sentence

Git keeps useful saved versions so you can compare changes, bring back saved work, and combine changes from a team.

A version is the project as it looked at one point. A snapshot is a way to think about that recorded state, like a photograph of the project. A commit is a saved version with a message and links to earlier commits.

You decide when to record a commit. Saving a file in your editor and making a Git commit are different actions. Git does not automatically remember every keystroke.

Your problemWhat Git helps you doWhy it matters
“What changed?”Compare two recorded versions.Find the exact change instead of guessing.
“The project worked yesterday.”Check and recover previously recorded content.Repair a mistake with evidence.
“Can I try a different idea?”Make a branch: a separate set of related changes.Experiment before combining the idea with the main work.
“We both changed the project.”Combine changes and identify conflicting edits.Keep useful contributions from more than one person.
“Why did we change this?”Read commit messages and review history.Help your future self and teammates understand the decision.

Try it: save, make a mistake, recover

This small project has one sentence. First record the mistake, then recover the correct sentence from version A and record the correction. Watch the saved history grow.

What the buttons represent

This browser model simplifies the steps. In real Git you edit a file, select content for the next commit by staging it, then commit. “Use this version” here changes the working sentence; it does not delete the saved history. “Save a version” creates a new saved version.

Six words, introduced through the project

▤ Repository

The project together with its saved versions and Git settings. Think “project + recorded story,” not just a folder of latest files.

● Commit

A saved project version with a message and links to earlier commits. “Add the planet facts” is a useful message.

⑂ Branch

A name pointing to one saved commit. New commits on that branch move the name forward. You can try a new title on a branch before combining it with the main work. The branch name points to a commit; making a branch does not copy the whole folder.

⇄ Diff

A comparison showing what changed between two states. Removed and added lines help you check the change.

⋈ Merge

Combine sets of related changes. If you changed the title and your friend added a fact, both changes may fit together.

! Conflict

Git needs your decision because it cannot automatically combine an edit. If you and your friend choose different titles, you decide the intended final title.

Do not memorize every command now. First say what problem each word describes. The later lessons show the exact commands and their effects.

Git and GitHub are related, but different

01

Your computer: Git

Record and check project history locally. You can make commits without an internet connection.

ABC
push →send commits← fetchdownload updates
02

A shared place: GitHub

Keep a shared Git project online, discuss changes, review proposed work, and choose who has access. Others can work with that shared repository.

Your changeTeammate reviewChecks

Git is the tool that keeps saved project versions. GitHub is one website that stores shared Git projects and gives people tools to work together. You can use Git without GitHub. A local commit is not on GitHub until you send it to the remote, normally with a push.

A pull request asks to combine proposed changes with a receiving branch and gives people a place to review them. Opening a pull request does not automatically merge or publish your project.

Quick check: I committed while offline. Can my friend see it on GitHub?

No. The commit is only on your computer. You must send it to the shared project when you have access. Commit and push are separate steps.

Quick check: Git found a conflict. Has it decided whose answer is correct?

No. You check both needed changes, choose or combine the correct content, and test the result. Git cannot decide the project’s requirements for you.

What Git does not promise

Common assumptionMore accurate idea
“Git saves every edit automatically.”A commit records selected content when you create it. Unsaved or never-recorded work may be lost.
“Git is my complete backup.”History in one local repository is still on that computer. Keep appropriate remote copies and backups; do not rely on Git for everything.
“Git checks whether my answer or code is correct.”It records and compares content. People and tests check correctness.
“GitHub is required to use Git.”Local Git works independently. Hosting adds sharing and collaboration.
“A merge always combines everything correctly.”Some edits conflict. Even a clean text merge needs review and tests.

What to remember

  • Git helps you understand and manage recorded project changes.
  • You choose when to make a commit; saving a file alone does not make one.
  • Git keeps your chosen versions; GitHub helps you share and review them.
