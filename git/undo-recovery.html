Undo a mistake and find saved work

Choose an undo command by what you want to keep. Learn how files, staging, commits, and shared history change in each case.

Need help with HEAD, index, staging, or diff?
Your file
What you are editing now. Git calls the project files the working tree.
Staging area = index
The file content you chose for the next commit. These are two names for one place.
HEAD
Tells Git which saved commit you are using, usually through your current branch.
Diff
A comparison showing added and removed lines between two versions.
Watch these change with one file →

By the end, you can…

  • Undo staging without throwing away the edited file.
  • Undo a shared change with a new correction.
  • Find a lost commit and keep it under a rescue branch.

First say what went wrong

“Undo” can mean several different things. Did you choose the wrong file for the next commit? Edit the wrong line? Save the wrong commit? Send it to others? Read git status, git diff, and git diff --staged first.

What you needCommandWhat changes
Remove a tracked file’s changes from the next commit, keep your edits.git restore --staged -- notes.txtStaging returns to the current saved version. Your file stays edited.
Throw away unstaged edits to a tracked file.git restore -- notes.txtYour file is replaced by the staged version. Save any wanted edits elsewhere first.
Undo a commit already shared with others.git revert COMMITAdds a new commit that reverses the selected change. Replace COMMIT with the checked ID.
Change the last private commit.git commit --amendMakes a replacement commit from staging and lets you edit its message. The ID changes.
Move a private branch back but keep all chosen content and files.git reset --soft TARGETMoves the branch. Staging and files stay. TARGET is the checked destination commit.
Move a private branch back, keep files, remove changes from staging.git reset --mixed TARGETMoves the branch and resets staging. Files stay.
Make the branch and tracked files match a target.git reset --hard TARGETMoves the branch, replaces staging and tracked files. It can discard edits and remove untracked files in the way.

Undo shared work by adding a correction

Before
→git revert C
After

In a real command, replace C with its actual ID. Inspect it with git show COMMIT first. A revert can conflict if later work changed the same lines. Resolve, add, test, and use git revert --continue, or stop with git revert --abort.

Revert changes files in Git. It does not undo a database change, recall an email, or disable a leaked password. Handle those systems separately.

More detail: undoing a merge commit

A merge has two parents. git show --no-patch --pretty=raw MERGE lists them. git revert -m 1 MERGE means keep parent 1 as the main line and reverse the merge’s change relative to it. Check the parent choice first. The old merge links still exist, so merging the same old branch again may not bring back the reverted effect. A reviewed new fix or a revert of the revert may be needed.

Find a commit after a branch moved away

Reflog is Git’s local list of movements: “main moved here after commit,” “HEAD moved there after reset.” It can help find committed work that a branch no longer points to.

  1. Read the movement list

    Look for the time and message before your mistake.

    Type this in your terminal
    git reflog --date=iso

    What you should see: A list of local events and commit IDs.

  2. Inspect the candidate

    Replace OLD_TIP with the ID from the event you found.

    Type this in your terminal
    git show OLD_TIP

    What you should see: The wanted files and changes are in this commit. Do not guess based only on its position in the list.

  3. Give it a name before doing more recovery

    Choose an unused rescue name. This does not move main or overwrite files.

    Type this in your terminal
    git branch rescue/my-work OLD_TIP

    What you should see: The saved work is reachable through rescue/my-work.

  4. Choose how to use the rescued work

    Compare it with the current project. You may need one file, one commit, or the whole branch.

    Type this in your terminal
    git log --graph --oneline --all

    What you should see: You have both versions available while deciding. Test after bringing back the wanted change.

Reflogs stay on the computer where the movements happened, can expire, and are not downloaded by a new clone. Git may eventually remove stored commits that no branch or retained record reaches. A file never added or committed is not something reflog can reliably recover. Check editor history or backups for that case.

Put unfinished edits aside for a short time

A stash is a temporary saved set of edits. It can help when you need to switch tasks before making a commit. First inspect what you are saving.

  1. Save tracked and new files temporarily

    -u includes untracked files. Ignored files are still left out.

    Type this in your terminal
    git stash push -u -m "Notes before urgent fix"

    What you should see: The chosen edits move into a stash entry. Read status to see what remains.

  2. Find and inspect the entry

    Number 0 is the newest entry. Its position can change when you make more stashes.

    Type this in your terminal
    git stash list
git stash show -p 'stash@{0}'

    What you should see: You can read the saved change before applying it.

  3. Apply and keep the saved entry

    Use apply so the saved entry remains while you check the result.

    Type this in your terminal
    git stash apply 'stash@{0}'

    What you should see: The edits return, or Git reports conflicts. Check and test before deciding to drop the entry.

git stash pop applies and removes an entry only after a successful application; it normally keeps the entry on conflicts. There is no git stash --abort. Preserve any edits that existed before applying it before undoing the attempt. git stash branch rescue/wip 'stash@{0}' can apply the edits around their original starting commit and removes that entry on success. Inspect carefully.

-a also saves ignored files, which may include large local data. For work you want to keep longer, prefer a branch with commits.

Before deleting or replacing content

git clean -nd previews untracked files and folders that a clean could remove. It does not remove them. -x includes ignored files too, such as a local database or environment. Read every path before any actual deletion.

Reset used with a path is different from reset used with a target commit: git reset HEAD -- notes.txt changes staging for that path and does not move the branch. Use the clearer restore --staged form while learning.

What to remember

  • Unstage keeps your file edits; restore without --staged can replace them.
  • Revert adds a correction to shared history. Reset can move a branch and replace files.
  • Find a lost commit, inspect it, and create a rescue branch before more changes.
