More tools for real project problems

Copy one fix, work in a second folder, reuse a conflict fix, and understand projects with large files or limited history.

Need help with HEAD, index, staging, or diff?
Your file
What you are editing now. Git calls the project files the working tree.
Staging area = index
The file content you chose for the next commit. These are two names for one place.
HEAD
Tells Git which saved commit you are using, usually through your current branch.
Diff
A comparison showing added and removed lines between two versions.

Copy one fix to another branch

Cherry-pick applies one commit’s change to your current branch. Example: main has a bug fix and a later new feature. An older release needs only the fix.

Before
Before
main:    A─B─F─N
release: A─R
F = fix; N = unrelated feature
→On release: cherry-pick the ID for F
After
After
release: A─R─F′
The fix is copied. N is not.

  1. Inspect the source change

    Replace COMMIT with the fix’s checked ID. Check whether it needs other earlier changes.

    Type this in your terminal
    git show COMMIT

    What you should see: Only the wanted fix is selected, and its dependencies are understood.

  2. Use the destination branch

    Start with saved work.

    Type this in your terminal
    git switch release/maintenance

    What you should see: Status names the intended release branch.

  3. Apply and record the source

    -x adds the original commit ID to the new commit message.

    Type this in your terminal
    git cherry-pick -x COMMIT

    What you should see: A new commit usually has a new ID because it has a different parent. Run the release tests.

For a conflict, edit, add, check, then git cherry-pick --continue; stop with git cherry-pick --abort. Copying a merge commit requires choosing a parent with -m and careful review. Do not use repeated cherry-picks to replace a clear shared-branch merge policy.

Keep unfinished work while opening a second task

A worktree gives the same repository another working folder. Each folder has its own files, staging area, and HEAD; commit storage and branch names are shared. It is useful for an urgent fix while the first folder has unfinished edits.

Create a new folder and a new branch named hotfix
git worktree add ../project-hotfix -b hotfix main
git worktree list

Your original folder and edits stay. Work in project-hotfix for the urgent change. Each folder may need its own installed dependencies. Git usually prevents the same branch from being checked out in both folders. When the second folder is clean and finished, use git worktree remove ../project-hotfix. Inspect it before removing.

Remember a conflict fix, then check it

Rerere is Git’s name for remembering a conflict resolution and trying it again when the same conflict returns. Enable it for a practice project with git config --local rerere.enabled true. Use git rerere status and git rerere diff to inspect.

A remembered answer can be wrong in a new context. Read and test the result. rerere.autoupdate also changes whether the result is staged automatically, so check that setting before relying on it.

Merge optionWhat it keeps
git merge -X ours featureFavors your side for conflicting parts, while still taking nonconflicting changes from feature.
git merge -s ours featureRecords feature as merged in the history, but keeps your entire current project tree and ignores feature’s file contents.

These are different operations. Neither one decides the correct application behavior for you.

When a project does not contain the files you expect

FeatureSimple meaningIf it causes a problem
SubmoduleA project records a particular commit from another repository.Read .gitmodules and git submodule status. Follow the project’s init/update steps and check access. The referenced commit must be available in that other repository.
Git LFSGit stores a small pointer file; a separate service stores the large file.If an image is only pointer text, check LFS installation, download, access, and quota. Do not replace the pointer with guessed content.
Shallow cloneOnly some recent history was downloaded.Check git rev-parse --is-shallow-repository. Fetch more history or unshallow when needed for old changes or merge bases.
Partial cloneSome stored file content is downloaded only when needed.An old-file read may need network access. Check the missing-object error and connection.
Sparse checkoutOnly selected tracked folders appear in your working folder.A missing path may be outside that selection. It has not necessarily been deleted from Git.
AttributesA .gitattributes file controls handling of selected paths.Check line endings and diff/merge handling before a large formatting or normalization change.
Small .gitattributes example — adapt it to the project’s existing policy
* text=auto
*.sh text eol=lf
*.png binary

LF and CRLF are two line-ending forms used by different systems. Changing them can make every line appear changed. Keep a whole-project normalization separate from a functional change. Do not run git add --renormalize . without reviewing the intended policy and resulting changes.

A case-only rename may be missed on a file system that treats Notes.txt and notes.txt as the same name. Use an intermediate name with git mv, then the intended spelling, and check the staged result.

Give a release commit a stable name

A tag names a particular saved version. An annotated tag also has a message and creator information. Use the team’s chosen release commit and version.

Example release steps — inspect the current commit before tagging
git tag -a v1.2.0 -m "Release 1.2.0"
git show v1.2.0
git push origin v1.2.0

A normal branch push does not send every tag. Push the intended tag explicitly. Avoid moving a published release tag because others may already have used its old value. GitHub Releases adds notes and downloadable files around a tag; check that any published build came from the intended commit.

What to remember

  • Cherry-pick copies a selected change; worktree opens another working folder.
  • A reused conflict fix still needs review and tests.
  • Missing files can come from submodules, LFS, or a limited checkout; read the specific error before changing history.
