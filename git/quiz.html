Need help with HEAD, index, staging, or diff?
Your file
What you are editing now. Git calls the project files the working tree.
Staging area = index
The file content you chose for the next commit. These are two names for one place.
HEAD
Tells Git which saved commit you are using, usually through your current branch.
Diff
A comparison showing added and removed lines between two versions.

Read or print all questions and answers
You choose text A with git add, then edit the file to B. What does git commit save?

A, the content chosen for this commit

Git saves staging, which still holds A. The later edit B stays in your file.

Review this topic
What does HEAD tell Git?

Which saved commit you are using, usually through your current branch

For example, HEAD names main and main points to commit A. A new commit on main moves main forward.

Review this topic
Are the index and the staging area two different places?

No. They are two names for the content chosen for the next commit

git add updates the index, which is the staging area. A later file edit does not change this chosen content.

Review this topic
At one point, HEAD has Hello, staging has Hi, and your file has Good morning. What does git diff show?

Hi changed to Good morning

Plain git diff compares staging with your file. Use git diff --staged to compare Hello with Hi.

Review this topic
Which command shows the changes chosen for your next commit?

git diff --staged

It compares the current saved commit with staging. Plain git diff compares staging with your file.

Review this topic
You put an already tracked .env file in .gitignore. Why does Git still report its edits?

Ignore rules do not stop tracking an existing file

Remove it from tracking with a reviewed git rm --cached if needed. If it held a secret, disable the secret too.

Review this topic
Your files include a bug fix and an unrelated experiment. What helps you save just the fix?

Choose only the fix’s files or changed lines, then read the staged diff

A commit with one purpose is easier to review and undo. git add -p lets you choose small groups of lines.

Review this topic
Git says switching branches would overwrite your edits. What should you do first?

Keep the edits with a commit, a checked stash, or a second working folder

Read the edits first, then choose how to save them. Do not discard the work Git is trying to protect.

Review this topic
origin/feature says you are up to date. Could someone still have pushed new work?

Yes. origin/feature is only your last-known server position

Fetch to update it. It does not check the server continuously.

Review this topic
What does git fetch origin do to your current branch and files?

Downloads shared history but leaves this branch and files as they are

It updates your last-known remote positions. Combining the downloaded work is a separate action.

Review this topic
Why can git pull --ff-only refuse even after a successful fetch?

Both sides made new commits, so moving the name alone cannot combine them

Read both sides and choose a merge or a suitable rebase.

Review this topic
What does normal git fetch --prune clean up?

Your local records of remote branches deleted on the server

It tidies the usual branch tracking records. Tags and custom fetch mappings can need separate settings.

Review this topic
Main is at B and feature is A → B → C. Can main fast-forward to C?

Yes, because C already includes B in its earlier history

Git can move main to C without creating a new merge commit.

Review this topic
Which three file versions does a simple three-way merge use?

The shared starting version and the two branch versions

The starting version lets Git see what each side changed.

Review this topic
Git combined the text without a conflict. What should you do next?

Read the result and test the combined behavior

Two text changes can fit together but make incompatible assumptions in the program.

Review this topic
After a squash saves one combined change, is feature recorded as a second parent?

No. The squash commit has one parent

It can include the file changes without keeping the source branch as a merge parent.

Review this topic
During rebase, which side is called ours?

The new starting work plus changes already applied onto it

Theirs is the original commit being applied now. Read both contents rather than guessing from the names.

Review this topic
Your editor offers Accept both for two conflicting settings blocks. What should you do?

Write one valid result with the required values from both changes

Keeping both text blocks can create duplicate keys or invalid JSON. Check the final values and format.

Review this topic
After you fix a conflict, what does git add do?

Chooses your final file and marks that file as resolved

You still need to read the chosen change, run tests, and continue the operation.

Review this topic
One branch deleted a file and the other edited it. What should you decide?

Whether the final project needs the file, then stage that choice

For an intended deletion use git rm; for an intended file, edit and add it. Read the task requirements first.

Review this topic
You run git rebase main while on feature. Which branch normally moves?

Feature, the branch whose changes are being applied again

Main is the new starting point and stays where it is. The rebase is local until you separately push.

Review this topic
Rebase pauses on the second commit. What does --skip do?

Leaves out that commit’s change from the new list

Use it only if you checked that the change is already present or is no longer wanted.

Review this topic
Why keep a backup branch and read range-diff after rebase?

To compare the old and new changes and spot a missing or changed step

The backup keeps the old commits. Range-diff helps review the changes, and tests check the resulting behavior.

Review this topic
How do rebase --abort and --quit differ?

Abort returns toward the starting state; quit leaves the current state

Quit stops managing the rebase but leaves the current files, staging, and commit position. Read status before choosing.

Review this topic
What does an accepted force push mainly change?

The position of the targeted server branch

Earlier commits may remain in other copies, but that branch can stop including a teammate’s work.

Review this topic
Why give force-with-lease an exact EXPECTED commit ID?

It accepts only if the server branch is still at that saved ID

If a teammate pushes after you checked, the ID differs and the replacement is refused. A later fetch does not change your saved exact ID.

Review this topic
Your editor fetches a teammate’s new commit in the background. Why can a default lease become weaker?

The last-known server position can advance before you read the new work

A lease without an exact expected ID may then permit replacing that new position. It has not checked whether you kept the new changes.

Review this topic
An exact-ID lease was rejected. What next?

Read the new remote commits and decide how to keep the needed changes

Do not just update the expected ID and resend the same replacement. That can remove the work the rejection protected.

Review this topic
Which command usually undoes a shared bad commit while keeping the old history?

git revert

It adds a correction that reverses the selected change in the current files. Resolve conflicts and test if needed.

Review this topic
You found a lost commit in reflog. What is a useful first recovery step?

Read it with show, then give it a rescue branch name

The name keeps the found commit available while you decide how to recover it. Main and your current files need not move.

Review this topic
Can reflog reliably recover a deleted file Git never stored?

No. Git may never have saved its contents

Reflog records branch movements, not every editor change. Check editor history or other backups.

Review this topic
Applying a stash gives conflicts. What is true?

The saved stash can remain, and there is no stash --abort

Keep any edits that existed before applying it. Resolve and test, or carefully undo only the attempted application.

Review this topic
What does git diff main...feature show?

The shared starting files compared with feature’s files

For diff, three dots compare the merge base with the branch on the right. For log, three dots select separate commits from both sides.

Review this topic
A blame entry names a developer. What does that tell you?

Which commit last changed the selected line under that calculation

Read that commit and its reason. Formatting or moved lines can affect the result; it does not by itself identify who caused a bug.

Review this topic
An old commit cannot be tested because a required package is unavailable. What should bisect do?

Mark it untestable when appropriate, using skip or exit 125

A setup failure is not proof of the bug you are searching for. Use the same reliable test across the range.

Review this topic
What does git log -S 'text' help find?

Commits that changed how many times that text occurs

Read the matching commits. Use -G for a pattern search in added or removed lines instead.

Review this topic
A reviewer approved, but a required test failed. Can the PR normally merge under that rule?

No. The required test must pass too

Approval and test results are separate requirements. Opening or approving a PR does not merge it.

Review this topic
After a squash merge, where should ordinary new work start?

On a new branch from the updated base, usually main

The old feature commits were not kept as parents of the squash commit. Reusing the old branch can confuse the next PR.

Review this topic
Why share range-diff after rewriting a PR branch?

It helps reviewers compare the old and new lists of changes

They can check conflict fixes, missing work, and edits made during rebase. It does not replace tests or approval.

Review this topic
What helps you build practical Git skill?

Predict the result, try it in a practice project, and check files and history

Explaining the observed change helps you use the command in a new situation too.

Review this topic
A person has Read access. Can a personal token give them Write access just by asking for it?

No. A user token cannot add access its owner does not have

Token permissions limit the owner’s existing access. The project grant must allow the action as well.

Review this topic
Which usual organization-project role allows code pushes without full settings control?

Write, with the branch rules still applying

Choose the access needed for the task. Write is different from Admin, and Triage does not grant ordinary code pushes.

Review this topic
A private project opens in your browser, but terminal Git says not found. What should you check?

The terminal account and whether its credential can reach that project

The browser login and terminal key can represent different accounts. A token may also have the wrong project selected.

Review this topic
Does removing someone from one team disable every key they held?

No. Check other grants, deploy keys, apps, and job credentials too

Other teams, direct access, or separate project keys may still work. Verify that the old access is removed.

Review this topic
Does creating CODEOWNERS automatically make its approval required?

No. Enable the required code-owner review rule too

The file chooses reviewers. A separate rule makes their approval a condition for merging.

Review this topic
You require a single-parent history but allow only merge commits. What is wrong?

The settings conflict; allow a suitable squash or rebase method

The linear-history rule rejects merge commits because those normally have two parents.

Review this topic
Why test branch rules with a normal writer who has no allowed exception?

An admin or exception account may not see the intended block

Check both a refused direct push and a successful approved PR. Saving a rule alone does not prove it works.

Review this topic
A required test stays pending for merge-queue commits. What could be missing?

A workflow reporting that check for the merge_group event

Read the exact required name, event, and check source. The job must report for the revision GitHub is evaluating.

Review this topic
You committed a token and later deleted its text. What should you do first?

Disable or replace the exposed token at its provider

Old commits and other copies may still hold it. Removing visible text does not stop the old credential working.

Review this topic
Why is it dangerous to run a fork PR’s build in a powerful pull_request_target job?

The contributor’s code may get the job’s secrets or write access

Builds, package installs, and config files can run code. Keep untrusted code away from powerful credentials.

Review this topic
What does a verified commit signature tell you?

The exact commit matches an accepted signing key under the verification rules

It does not tell you that tests passed, someone reviewed it, or the code is free of bugs.

Review this topic
Only the release job needs to publish packages. How should you grant that access?

Give it only to the job that needs it

Test jobs do not need publishing access. Limiting their credentials reduces what a mistake or untrusted step could do.

Review this topic
A cherry-picked fix has a new commit ID. Is that expected?

Yes. Applying the change after a different parent usually makes a new commit

Read the fix’s required earlier changes and test it in the destination branch.

Review this topic
What does a linked worktree give you?

Another working folder with separate files, staging, and HEAD

The folders share stored commits and branch names. Your first folder’s edits can stay while you work on a separate task.

Review this topic
Why check a conflict fix reused by rerere?

It may repeat a wrong answer or an answer that no longer fits

Remembering old text does not prove it is correct with the new surrounding changes. Read and test it.

Review this topic
How do merge -s ours and merge -X ours differ?

-s ours keeps all our files; -X ours favors ours only for conflicting parts

The -s strategy records the other history but ignores its file contents. The -X option can still take nonconflicting edits from the other side.

Review this topic
Git says index.lock exists. What should you check first?

Whether another Git process is still writing in the project

The lock may protect an active command. Remove only a confirmed leftover lock when no process uses it, then read status.

Review this topic
Text merged without conflicts, but the program fails. What could explain it?

The two changes disagree in behavior even though the text fits

For example, one change renames a function while another calls the old name. Read and test the combined program.

Review this topic
After reverting a merge, why might merging the same old branch not restore its change?

The old merge links still exist even though revert changed the files

Plan a new corrective commit or a reviewed revert of the revert. Do not assume the old merge will be applied again.

Review this topic
Your copy lacks older commits needed to find a merge base. What should you check?

Whether it has limited history and whether the needed branches were fetched

A shallow clone downloads limited history. Fetch the missing depth or branches before relying on the comparison.

  • Read why a choice is right or wrong.
  • Try a real lab when you cannot yet explain the result.
