Sixty questions across fifteen topics test Git behavior, recovery, collaboration and GitHub controls, with an explanation for every choice.

You stage version A of a file, edit it to B, then run ordinary git commit. What is recorded?

Version A from the index

Commit records the staged snapshot. Later unstaged edits remain in the working tree.

What is a branch in Git?

A movable reference to a commit

Its tip moves as commits are recorded or references are deliberately updated.

You amend only the commit message. Why does the commit ID change?

The message is part of the commit object

Amend creates a replacement object, even if its tree content is unchanged.

Setting user.email to a teammate’s GitHub address gives you what?

Commit metadata, not their repository permissions

Authentication and authorization are independent of author-name/email fields.

What should you inspect to review the next ordinary commit’s content?

git diff --staged

It compares the index with HEAD, showing the staged changes.

A tracked .env file was added to .gitignore. Why does Git still show modifications?

Ignore rules do not untrack existing paths

Remove it from tracking deliberately and handle any historically exposed credentials separately.

Your working directory mixes an urgent fix with an unrelated experiment. What is a useful next step?

Stage selected paths/hunks and inspect the staged diff

A coherent commit lets the reviewer and future debugger understand one change.

Review this topic
A switch would overwrite your uncommitted work. What should you do first?

Preserve and inspect the work, or use another worktree

Commit, reviewed stash or a separate checkout avoids losing the original edits.

origin/feature says you are up to date. Does that guarantee the live server has no new commits?

No; the remote-tracking ref may be stale

Fetch before using it as current evidence of the server’s state.

Review this topic
What does git fetch normally do to your checked-out branch?

It updates remote information without integrating into that branch

It retrieves objects and updates refs according to fetch configuration.

Review this topic
Why might git pull --ff-only refuse after fetching?

The branches diverged and cannot be integrated only by moving the tip

Inspect and choose merge or rebase deliberately.

Review this topic
What does normal git fetch --prune remove?

Stale local tracking refs covered by the fetch refspec

It cleans your cached view of deleted remote refs; tag behavior needs separate configuration awareness.

Review this topic
When is a fast-forward possible?

The current target tip is an ancestor of the incoming tip

The branch can move to the descendant without creating a merge commit.

Review this topic
Which three snapshots matter in a simple three-way merge?

Common base, current side and incoming side

The base explains what each side changed independently.

Review this topic
A merge reports no conflicts. What have you learned?

Git found a textual combination, but behavior still needs testing

Different files or nonoverlapping edits can introduce semantic incompatibility.

Review this topic
After a squash commit, are the original feature commits necessarily ancestors of main?

No; the squash records combined content with a different parent relationship

The source branch ancestry is not preserved as a merge parent.

Review this topic
During rebase, which side is normally called ours?

The new base plus commits already replayed

The original commit currently being replayed is the theirs side.

Review this topic
Your editor offers Accept both for conflicting JSON values. What should you do?

Construct one valid result that satisfies both intended requirements

Concatenation can create invalid JSON or duplicate contradictory keys.

Review this topic
What does git add do to a manually resolved conflict?

Records your chosen resolution in the index

It marks the path resolved; you must still review and test it.

Review this topic
A delete/modify conflict appears. What is the correct general response?

Decide whether the final design needs the file, then stage deletion or retained content

A delete/modify conflict is a product decision, not merely a marker cleanup.

Review this topic
Rebasing feature onto main changes which branch in the normal workflow?

The feature branch being replayed

Main supplies the new base; rebase does not automatically move main.

A rebase stops on a conflict in the second commit. What does --skip do?

Omits that commit’s replayed change

Use it only when the change is verified redundant or deliberately unwanted.

Why keep a backup tip and use range-diff after a rebase?

To compare the old and new patch series and inspect changed or omitted work

This supports review and recovery, but tests are still needed.

What is a key difference between rebase --abort and --quit?

Abort attempts to restore the pre-rebase state; quit leaves the current state

Choose based on the actual operation and desired recovery.

What does an accepted force push principally change?

The targeted remote reference

Old objects may remain elsewhere, but the branch may stop reaching teammates’ commits.

Why is an explicit --force-with-lease=ref:EXPECTED useful?

It requires the live remote tip to match the pinned object ID

It detects concurrent tip changes regardless of a later tracking-ref update.

Its tracking-based expectation may advance without your review

An unqualified lease can accept replacing that newly observed tip; pin the reviewed expectation.

An explicit lease was rejected. What should you do?

Inspect the new remote commits and account for them before retrying

Refreshing the expected ID without preserving work defeats the reason for the rejection.

Which operation usually undoes a public bad change while preserving shared ancestry?

git revert

It records a new inverse change; resolve conflicts and test the resulting behavior.

You found a missing committed tip in reflog. What is a useful first recovery action?

Inspect it and create a rescue branch at that ID

A named reference protects the candidate before more state changes.

Can reflog reliably recover a never-tracked file removed by a cleanup command?

No; Git may never have recorded its contents

Use external backups or editor/filesystem recovery where available.

Review this topic
A stash application conflicts. Which statement is correct?

The stash can remain, and there is no stash --abort command

Preserve pre-existing work and resolve or recover deliberately.

How does git diff A...B differ from git log A...B?

Diff compares merge-base to B; log selects the symmetric difference

Dot syntax must be interpreted in the command’s context.

The selected line’s last modifying commit under that blame calculation

Read the commit and context; formatting and moves can affect attribution.

As untestable when appropriate, using skip/exit 125

Do not confuse an environment failure with the regression you are searching for.

Which changes altered the occurrence count of that text?

Use -G for matching added/removed lines by regex; inspect the relevant path/range.

A pull request is approved but a required test failed. Is it ready to merge?

Not under a policy requiring that check to pass

Human review and automated checks are independent evidence.

Review this topic
After squash-merging a feature, where should ordinary new work usually start?

From the updated base branch on a new feature branch

The old feature IDs were not preserved as main’s ancestors; endless reuse can complicate later comparisons.

Review this topic
What is a good reason to include range-diff after rewriting a PR branch?

It helps reviewers compare the old and new patch series

Reviewers can focus on conflict resolutions, omissions and changes introduced during the rewrite.

Review this topic
Which practice most improves practical Git skill?

Predict state changes, execute in a disposable repo, then verify the graph and content

This builds a transferable mental model rather than a fragile command memory.

Review this topic
A Read-only user creates a PAT with broad requested scopes. Can it give them repository Write access?

No; a user token cannot exceed the owner’s access

Scopes further constrain identity capabilities; they do not grant missing repository roles.

Review this topic
Who normally needs code push capability without full sensitive administration?

A contributor with Write access, subject to rules

Grant only the task’s needed repository role and credential permissions.

Review this topic
The browser can view a private repo but terminal Git says not found. What should you check?

Whether the terminal credential is the same identity and has that repo selected

Browser sessions and CLI/SSH credentials can represent different accounts.

Removing an employee from a team is enough to revoke every automation credential they possessed. True?

No; review other grants, deploy keys and app/automation access too

Effective access and standalone credentials may have additional ownership/lifecycle paths.

No; enable the relevant required-review policy too

The file routes ownership; enforcement is a separate repository rule.

The policies conflict; allow a compatible squash or rebase method

Linear history rejects merge commits on the protected target.

Why test rules using a non-bypass contributor?

An admin or configured bypass actor may not experience the intended restrictions

A saved setting is not proof that normal contributors are gated correctly.

The workflow does not report the required check for the merge-group event

Inspect exact event, job/check name and trusted source.

A token was committed and then deleted in a later commit. What is the first security action?

Revoke or rotate the exposed token

Old commits and external copies may still contain it; visibility cleanup does not invalidate credentials.

Untrusted code can execute with the trusted job’s secrets or write capability

Build/install/configuration steps can run attacker-controlled behavior.

What does a verified commit signature establish?

Evidence about the object and a signing key under the verifier’s policy

It does not replace review or prove functional correctness.

Only the release job needs package publishing. How should workflow permissions be designed?

Grant that capability narrowly to the job that needs it

Minimize credentials available to other jobs, especially untrusted validation.

No; applying the patch in another parent context creates a new commit

Inspect dependencies and test the new context.

What does a linked worktree provide?

Another working directory/index while sharing repository objects and refs

It is useful for parallel tasks without overwriting the first checkout’s files.

Why review a rerere-reused resolution?

It may repeat an incorrect or contextually outdated decision

Reusing text is not a correctness proof.

How does merge -s ours differ from merge -X ours?

-s ours keeps our tree while recording ancestry; -X ours favors ours in conflicting hunks

The latter can still incorporate the other side’s nonconflicting changes.

Check whether an active Git process is using the repository

Only a confirmed stale lock should be removed; concurrent writers can corrupt intended state.

A semantic conflict

The text combined mechanically while assumptions or interfaces became incompatible.

After reverting a merge, merging the same old branch does not restore its change. Why?

The original merge ancestry remains recorded

Revert changed content; plan new corrective commits or a reviewed revert of the revert.

Whether it is shallow and whether the necessary refs/ancestors were fetched
