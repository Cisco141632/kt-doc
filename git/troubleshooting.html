The development incident clinic

Thirty common Git and GitHub problems, organized by symptom, evidence, correction and a result you can verify.

By the end, you can…

  • Classify history, working-tree, conflict, access and policy failures.
  • Use targeted recovery rather than broad destructive commands.
  • Document the cause and verified outcome.

Start with evidence

→

→

Shell example — read the context before running
git status
git branch -vv
git log --graph --oneline --decorate --all -20
git diff
git diff --staged

For a remote problem, record the exact server error with credentials redacted. For local data loss, stop and preserve evidence before cleanup. An error message is not a complete diagnosis: “rejected” can mean ancestry, access or policy.

Find your symptom

30 troubleshooting cases

remote Push rejected: non-fast-forward

Likely cause

The server has ancestry your proposed tip does not contain, or you rewrote published commits.

Gather evidence

Fetch, then inspect git log --left-right --graph HEAD...origin/feature.

Resolve deliberately

Integrate unreviewed teammate work. If this is an agreed rewrite, use the explicit-lease procedure after preserving the intended history.

Verify the outcome

A normal push advances to a descendant, or an authorized lease protects the exact expected tip.

Review the related lesson →
remote Force-with-lease rejected

Likely cause

The server tip differs from the expected value.

Gather evidence

Inspect the new remote tip and compare it with the pinned expectation.

Resolve deliberately

Coordinate and account for the new commits. Do not merely refresh the expectation and retry the same overwrite.

Verify the outcome

Both contributors’ intended changes remain, and the final graph matches the agreement.

Review the related lesson →
workflow I committed on the wrong branch

Likely cause

The checked-out branch was not the intended destination.

Gather evidence

Inspect status, branch, the commit and whether it has been pushed.

Resolve deliberately

Create a rescue/feature branch at the current tip first. Correct the original branch using a deliberate private reset or shared-history revert.

Verify the outcome

The work is reachable on the intended branch and no shared history was silently replaced.

Review the related lesson →
workflow Detached HEAD

Likely cause

HEAD names a commit rather than a branch.

Gather evidence

Inspect git status and log -1. Determine whether you created new useful commits.

Resolve deliberately

Create a branch at the current tip before switching away if it contains useful work.

Verify the outcome

The new branch names the work you need to keep.

Review the related lesson →
recovery A reset or rebase made commits disappear

Likely cause

A reference moved; the old commits may still be in the local object database.

Gather evidence

Inspect local reflog timestamps/messages and git show for candidate tips.

Resolve deliberately

Create a rescue branch at the verified old tip, then compare and recover deliberately.

Verify the outcome

The desired files/commits are reachable and tested. Reflog is not a promise for unrecorded files.

Review the related lesson →
workflow Local changes would be overwritten

Likely cause

Switch/merge would collide with working-tree changes.

Gather evidence

Read status, staged diff, unstaged diff and relevant untracked files.

Resolve deliberately

Commit coherent work, use a reviewed stash, or create another worktree; then retry the intended operation.

Verify the outcome

The original work is preserved and the new operation starts from understood state.

Review the related lesson →
conflicts You have unmerged paths

Likely cause

An integration operation is paused with unresolved index entries.

Gather evidence

Read git status to identify the operation; inspect git ls-files -u.

Resolve deliberately

Resolve each path, stage the intended result, test and use the matching continue command.

Verify the outcome

The unresolved-path list is empty and the operation completed with the intended behavior.

Review the related lesson →
conflicts Accept current kept the wrong code

Likely cause

The labels were interpreted without the operation context.

Gather evidence

Inspect base and stages 2/3; during rebase ours is the rebased-so-far side.

Resolve deliberately

Reconstruct the intended combined result from the requirements and snapshots. Do not blindly repeat a side-selection shortcut.

Verify the outcome

Review the staged diff and test both branches’ requirements.

Review the related lesson →
conflicts Rebase conflicts again in the same file

Likely cause

Different commits in the replay sequence touch the same area.

Gather evidence

Use rebase --show-current-patch and inspect the current step.

Resolve deliberately

Resolve each commit in context; skip only if the change is verified redundant or intentionally dropped.

Verify the outcome

The full replay finishes and range-diff shows no accidental missing patch.

Review the related lesson →
recovery Stash pop left conflicts and still lists the stash

Likely cause

The application did not succeed, so Git retained the stash.

Gather evidence

Inspect status, stash list and stash show; preserve any work that existed before application.

Resolve deliberately

Resolve and test, or restore only the known attempted changes after preserving work. There is no stash --abort.

Verify the outcome

The desired work exists and the stash is dropped only after verified successful recovery.

Review the related lesson →
files A file in .gitignore still changes in Git

Likely cause

It is already tracked, or another rule is responsible.

Gather evidence

Use git ls-files -- path and git check-ignore -v -- path as appropriate.

Resolve deliberately

If it should stop being tracked, review git rm --cached -- path and commit the removal. Handle old secrets separately.

Verify the outcome

Future ordinary status does not track the file, and required example configuration remains.

Review the related lesson →
security A token was committed

Likely cause

The credential may be available in history or other copies.

Gather evidence

Identify credential owner, scope, usage and the exposed refs/copies without spreading the value.

Resolve deliberately

Revoke/rotate first, then coordinate any history cleanup and downstream updates using the provider’s incident process.

Verify the outcome

The old credential is invalid and required cleanup/prevention steps are documented.

Review the related lesson →
remote Current branch has no upstream

Likely cause

The local branch lacks a configured tracking relationship.

Gather evidence

Inspect branch -vv and the intended remote branch.

Resolve deliberately

Use an explicit push -u for the intended new branch or set the correct existing upstream.

Verify the outcome

branch -vv shows the intended target; no force is needed.

Review the related lesson →
access Repository not found

Likely cause

The URL may be wrong or the current identity lacks private-repository access.

Gather evidence

Check owner/repo, terminal account, selected token repositories, and organization access.

Resolve deliberately

Correct the URL or grant the necessary scoped access through the owner’s process.

Verify the outcome

A read operation succeeds as the intended account without credentials embedded in the URL.

Review the related lesson →
access Permission denied (publickey)

Likely cause

SSH is using an unrecognized/unavailable key or a disallowed organization credential.

Gather evidence

Inspect configured SSH identity, agent keys and account registration; do not print private-key content.

Resolve deliberately

Load/register the appropriate key and complete required authorization, or use the approved HTTPS flow.

Verify the outcome

Authentication identifies the intended account and repository access is separately verified.

Review the related lesson →
access 403 or resource not accessible

Likely cause

The credential, repository access or organization policy does not permit the operation.

Gather evidence

Read the exact response and check token permission, expiry, selected owner/repo, approval and SSO/network restrictions.

Resolve deliberately

Adjust only the missing legitimate permission or complete the required organization process.

Verify the outcome

The required operation succeeds while unrelated operations remain denied.

Review the related lesson →
rules GH013 / GH006 or protected-branch rejection

Likely cause

A repository rule is blocking the update.

Gather evidence

Read the named failed rule and effective branch rulesets.

Resolve deliberately

Use the required PR/review/check path or the documented emergency process; do not weaken rules to silence the error.

Verify the outcome

An approved change passes and an unauthorized direct update remains blocked.

Review the related lesson →
access Cannot push a workflow-file change

Likely cause

Workflow-specific permission may be missing in addition to Contents write, or rules block it.

Gather evidence

Inspect credential type, workflow scope/permission and applicable rules.

Resolve deliberately

Grant the needed narrow credential permission through the proper process, then get required review.

Verify the outcome

The intended workflow update succeeds without broad admin credentials.

Review the related lesson →
rules A required check stays pending

Likely cause

The expected check may not run for this event, branch, path filter or merge-queue commit.

Gather evidence

Compare the exact required check name and source with actual workflow events and job results.

Resolve deliberately

Fix the workflow/check contract. Include merge_group behavior when using a merge queue where needed.

Verify the outcome

The required result appears for the revision actually being evaluated.

Review the related lesson →
rules Approval vanished after another push

Likely cause

The team policy dismisses stale approval or requires review of the latest changes.

Gather evidence

Inspect the latest commit and effective review rule.

Resolve deliberately

Ask for fresh review with a focused description/range-diff of what changed.

Verify the outcome

An eligible reviewer approves the current work; do not self-bypass normal policy.

files Every line appears changed

Likely cause

CRLF/LF normalization or a formatter may have changed the whole file.

Gather evidence

Inspect .gitattributes, relevant config, diff statistics and whitespace-aware comparisons.

Resolve deliberately

Apply the team’s line-ending policy and isolate normalization from functional changes.

Verify the outcome

The remaining diff is intentional across supported platforms.

Review the related lesson →
files A case-only rename is missing

Likely cause

A case-insensitive filesystem may treat the two names as identical.

Gather evidence

Inspect tracked spelling with ls-files and the platform’s behavior.

Resolve deliberately

Use an intermediate git mv path, then the intended spelling, and inspect the staged rename.

Verify the outcome

A clean checkout on the supported platforms has the correct path and imports.

Review the related lesson →
conflicts Package lockfile conflict

Likely cause

Dependencies changed independently or tool versions produced different output.

Gather evidence

Read manifest intent and the pinned package-manager version.

Resolve deliberately

Resolve manifests, regenerate according to project guidance, inspect the lockfile diff and test.

Verify the outcome

Installation is reproducible with both intended dependency changes.

Review the related lesson →
remote Refusing to merge unrelated histories

Likely cause

The histories have no common ancestor, possibly because the wrong repository was selected.

Gather evidence

Verify remote identity, clone origin and both root histories.

Resolve deliberately

Fix a mistaken remote/clone. Use allow-unrelated-histories only for an intentional project combination with review.

Verify the outcome

The integrated history corresponds to the intended projects, with no accidental repository mix-up.

Review the related lesson →
history History or merge-base seems missing

Likely cause

The clone may be shallow or a needed ref has not been fetched.

Gather evidence

Inspect rev-parse --is-shallow-repository, fetch configuration and available refs.

Resolve deliberately

Fetch the required refs/depth or unshallow where appropriate, then repeat the analysis.

Verify the outcome

The relevant ancestors exist locally and the comparison is meaningful.

Review the related lesson →
history Bisect identifies an implausible commit

Likely cause

The test is flaky, environment-dependent or classified unbuildable revisions as product failures.

Gather evidence

Reproduce the candidate and parent with the same controlled test; inspect the bisect log.

Resolve deliberately

Stabilize the test and use skip for genuinely untestable revisions; repeat only with reliable evidence.

Verify the outcome

The candidate’s change explains a reproducible behavior transition.

Review the related lesson →
recovery Merging again does not restore reverted work

Likely cause

Reverting changed the tree but preserved the original merge ancestry.

Gather evidence

Inspect the original merge, revert and subsequent commits.

Resolve deliberately

Design a reviewed correction, new commits or a revert of the revert as appropriate; do not assume the old merge will replay.

Verify the outcome

The desired behavior returns without silently dropping later work.

Review the related lesson →
workflow index.lock exists

Likely cause

Another Git process may still be writing, or a previous process died.

Gather evidence

Check running Git/editor processes and repository activity before touching the lock.

Resolve deliberately

Let active operations finish. Remove only a confirmed stale lock when no process is using it, then inspect status.

Verify the outcome

Git operates normally without concurrent writes or lost index state.

Review the related lesson →
files Submodule path is empty or points to the wrong version

Likely cause

The parent records a submodule commit that may not be initialized/fetched or available to you.

Gather evidence

Inspect .gitmodules, submodule status, access and whether the referenced commit was pushed.

Resolve deliberately

Follow the project’s submodule update/init procedure and publish referenced commits in the proper repository.

Verify the outcome

The parent commit checks out with the intended reachable submodule version.

files A large file is only pointer text

Likely cause

Git LFS content was not downloaded or is inaccessible.

Gather evidence

Check LFS installation, object fetch status, permissions and quota.

Resolve deliberately

Use the project’s documented LFS setup/fetch process; do not edit the pointer into fake content.

Verify the outcome

The application opens the actual expected binary and the pointer remains correct in Git.

Write the useful incident handoff

Record the repository and branch, operation attempted, relevant old/new IDs, the observed failure, what was preserved, the correction and how you verified it. Include downstream impact on teammates, CI or releases. Avoid including tokens, private keys or unnecessarily sensitive code.

When the same issue repeats, improve the workflow: smaller changes, clearer branch ownership, better checks, stable formatting policy, documented credential setup, or an enforced server rule. A rescue command solves one incident; a better development habit reduces the next one.

Remember in 30 seconds

  • Read the exact failure and inspect the relevant layer.
  • Preserve recoverable work before changing more state.
  • Verify the outcome and improve the process that caused the incident.
